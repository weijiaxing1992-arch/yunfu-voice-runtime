# 批量通道变量与 FreeSWITCH 对照

`api uuid_setvar_multi <uuid> <name>=<value>;<name>=<value>...` 和同命令的 `bgapi` 已接入实际通话主循环。UUID 来自真实 CHANNEL_CREATE；桥接的两腿互不共享变量。本地呼入只有一个实际通道。

```text
api uuid_setvar_multi <uuid> customer=中文客户;stage=welcome;note='含;分号';old=

api uuid_getvar <uuid> customer

```

普通成功正文是 `+OK\n`。客户端仍应读回关键变量，尤其批量请求可能部分成功。赋值按顺序执行，同名项最后一次生效；空值和缺等号项均删除变量。单引号保护分隔符并去除配对引号，双引号没有此保护作用。支持反斜线转义当前分隔符、引号、反斜线以及 n/r/t/s；未知转义保留。

`^^|a=1|b=2` 可指定一个 ASCII 非空白分隔符；空白、单引号、反斜线及非 ASCII 分隔符明确拒绝。分号列表外侧 ASCII 空格被修剪，单引号内和转义形成的空格保留。

| 场景 | RustSwitch 实际行为 | 固定原版对照范围 |
|---|---|---|
| 普通变量、Unicode、值含等号 | 逐项修改并可读回 | 同参数 API 与读回结果逐项核对 |
| 空值或缺等号 | 删除变量，getvar 为 `_undef_` | 按原版实际通话观测实现 |
| 列表包含空变量名 | 累积 `-ERR No variable specified\n`，其余有效项执行，至少一项成功再追加 `+OK\n` | 保留原版部分成功响应 |
| 不存在的通道 | `-ERR No such channel!\n` 后接用法行 | 原版同路径对照 |
| 无参数／只有 UUID | 分别返回用法行／ESL `-ERR no reply\n` | 不伪造写入成功 |
| 超过64项或16KiB、NUL | 在任何写入前拒绝整个列表 | 有界实现；不沿用原版超出数组后吞并尾部的行为 |
| 受保护身份、数组、变量展开 | 明确错误，其余有效项仍可执行 | 不提供原版完整变量容器和展开功能 |
| 每腿超过128变量或64KiB | 当前项错误，已完成项保留 | 自有资源保护差异 |

所有预算按 UTF-8 字节计算。新请求不能更新已结束通道，排队中已取消的请求不会开始修改。已开始执行的批次按主循环顺序结束；它不是事务回滚接口，也不负责把变量转换为录音、转码或其他未实现模块的副作用。

测试入口为 `esl_variables_test.go` 与 `tests/esl_variables_e2e.py`。后者建立真实 SIP 双腿、读回变量、检查双向 Rust RTP、挂机后再次呼叫，验证变量隔离和资源回收。原版原始帧与候选差分另见本轮验证报告；这些用例不代表全部通道变量兼容。
