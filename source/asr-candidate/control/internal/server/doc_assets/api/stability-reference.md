# 通话稳定性、资源保护与验证边界

文档版本：1.3.0；核对日期：2026-09-06。本章说明当前代码采取的保护及可观察证据，不承诺所有故障下通话无损，也不代表已通过单机万路验收。

## 通话卡住与媒体更新

媒体命令按工作进程的有界队列提交，控制面不再为每条命令启动一个独立协程。同一通话最多保留一个在途连接更新和一个最新待处理目标；连续早期媒体更新可以合并，最终接通目标取代尚未执行的旧目标。通话结束后不再提交残留连接更新，避免旧媒体地址覆盖最终地址或复活已结束通话。

控制面校验媒体响应的命令类型、会话及分配结果；不能仅凭 `ok=true` 判定成功。队列已满时明确返回背压，保留待释放资源并退避重试；工作进程明确拒绝释放、响应违约或管道超时则按该工作进程故障处理，回收该代会话。每个工作进程复用超时计时器，管道写入有期限，避免每条命令再创建超时执行任务。

这些处理保留既有建立通话、等待 ACK、取消、BYE、排空及最大通话时长约束。不能把“媒体一段时间无包”直接当作挂死：保持、静音或停发可能合法。完整的 SIP 会话刷新、注册、鉴权及原版通道状态机仍在[功能差距表](feature-audit.md)中列为待补齐。

## 媒体进程与异常流量

Rust 媒体控制输出采用有期限的整帧写入；输出消费者停止读取时，退出不再无限等待写线程。退出时先释放媒体引擎及其 UDP 端口，再等待受截止时间约束的输出清理。

媒体接收工作预算覆盖所有来源，包括最终会被来源校验拒绝的数据。超预算的 socket 暂停可读监听并在冷却到期恢复；恢复时主动调度尚未排空的数据，避免可读事件反复立即返回造成忙循环。冷却记录按 socket 有界，释放端口时同步清理，不创建逐通话或逐报文线程。正常媒体的速率校验、来源锁定、RTP/RTCP 校验和有限发送队列继续生效。

工作预算会主动限制异常流量；任何过载保护都不能据此承诺“永不丢包”。一个媒体进程失败时，该分片通话可能终止，其他健康分片继续服务。此实现不提供完整通话状态跨机接管。

## 管理面预算与错误合同

最多接受 **64 个管理 TCP 连接**；超过时由监听队列等待，直到连接释放或客户端超时。最多同时执行 **8 个重请求**，覆盖 XML 配置读取/保存/导出、文档读取/下载、完整运行配置保存及测试报告下载。第 9 个重请求在读取正文、执行业务之前收到 HTTP `503`、`Retry-After: 1` 和 `Error` JSON；客户端应退避，写请求仍遵守版本冲突与幂等规则。

健康、状态、指标、保护策略、排空及测试停止不占重请求额度，但仍共享 64 个连接上限。该边界限制管理请求的协程、编码与导出叠加，不限制整个进程的操作系统线程数量。配置及 XML 管理响应在锁内取得所需快照或完成状态提交，然后解锁再向客户端写入；慢客户端不再通过网络写入持锁阻挡其他管理操作。

峰值保护页面仍可配置最大活跃通话、最大建立中通话、CPS、突发及软阈值。后台的准入状态和拒绝原因反映实际运行结果；既有通话不会因调低准入上限被主动批量挂断。

## 新增控制进程观测

`GET /v1/status` 的 `controller` 提供 Go 控制进程的真实采样；压力测试的 `samples[].controller` 和 `final_status.controller` 对应隔离测试实例。历史报告可缺少该字段。后台总览及测试详情分别展示对应实例，不混用主服务和测试进程的数据。

资源采样最多每秒更新一次，无新增后台采样协程；队列和管理预算为查询时即时值，各字段不是原子事务快照。`peak_sampled_goroutines` 是观察到的采样峰值，可能遗漏采样间尖峰。`runtime_threads` 是 Go 拥有的存活线程，旧版 Go 不提供时为 null；它不是协程数，也不是 `gomaxprocs`。`cpu_cores_used` 为相邻成功采样的 CPU 秒差除以墙钟时间，可以大于 1，首次或无法采集时为 null。`go_memory_bytes` 为 Go 运行时映射内存扣除已归还堆页，不是 RSS，也不包含 Rust 子进程。

完整字段、可空类型与所有新增指标见 [HTTP 参考](http-reference.md) 和 [OpenAPI](openapi.json)。可选指标没有数据时不输出对应 Prometheus 样本，不伪装为零。

## 验证方式与尚待验收项目

仓库回归覆盖命令顺序、连续早期媒体合并、终止后禁止连接、错误响应、队列饱和、RPC 卡住、媒体输出阻塞、异常来源洪泛与冷却恢复、管理并发预算、慢配置读取及真实 SIP/RTP/RTCP 通话释放。`make test` 包含普通 UDP 和 connected UDP 两组真实本机通话；`make check` 检查编译风格、静态问题及文档一致性。实际执行记录与运行环境应单独随交付保存，测试定义存在不表示已执行。

完整的 FreeSWITCH 对照见 [145 条模块/构建目录审计及 35 个业务域](feature-audit.md)，机器结果见 [feature-audit.json](feature-audit.json)。目前原版运行时动态差分为零项，不能把静态源码核对或自研回归等同于原版兼容认证。

Linux 服务器提供后，需要固定 CPU、内存、网卡、内核、编译版本和业务模型，采用独立压力发生器测试 500/1000/2000/3000/5000/10000 并发、升降载、持续运行、信令洪泛、媒体洪泛、磁盘/工作进程故障。同时采集每个进程 CPU、线程、RSS、调度延迟、网卡/内核丢包、SIP 成功率与时延、双向 RTP 丢包/乱序/抖动、通话残留及释放耗时，并在相同条件下运行原版。仅在这些证据达到预先约定阈值后，才能陈述对应场景的容量与性能优势。


## 1.3 重复分支响应与资源上界

当固定上游返回多个成功分支时，当前原型选择一个对话，对其他分支发ACK并尽力发送BYE清理，不提供完整的多目标fork业务。旧实现对同一个未选中分支的重复200每次重新创建BYE事务，重复报文会放大事务和定时器占用。

当前按远端标签保留最多8个清理记录；同一分支至多一个受管理的BYE事务，仍按SIP要求响应ACK。去重期限为首次观察后的32秒，重复响应不会延长。清理完成后短期保留去重标记，通话回收时取消其附属定时器。超过分支记录上限或全局事务预算不足时，以稳定事务分支发送无状态BYE，不再增加清理定时器；这种降级不提供主动定时重试，不能描述为完整fork可靠性保证。

此修复限制重复信令对资源的放大，不等同于控制面崩溃恢复、无损迁移或完整FreeSWITCH会话宿主。原版对应的分叉、ACK/BYE次序、计时和事件合同仍需成对验收。

## 失败证据与采样中断

发生器失败后，控制器在已有总期限内最多花 1.5 秒读取一次子实例状态，不延长原任务总时限，也不覆盖原失败原因。`final_status_phase` 区分失败诊断与成功拆线收敛；`final_status_sampled_at` 记录本次读取完成时刻。读取失败时 `final_status=null` 并保留错误，不沿用媒体中的旧快照。具体实测见[本轮记录](verification-2026-09-06.md)。

外部验收工具仅对网络采样中断允许有界恢复，第三次连续中断即失败，成功读取不会延长原总期限。HTTP 业务错误、JSON 合同错误和作业归属错误不重试；耗时与中断次数保留在摘要中。该恢复机制不降低媒体验收门槛。
