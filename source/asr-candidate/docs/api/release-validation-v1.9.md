# 云蝠 Voice Runtime 1.9：总览压测观测与语音智能体方向

本轮研发定位调整为高性能实时语音内核，首期服务电话语音智能体，保留必要的 FreeSWITCH 接口适配。完整研发边界、性能目标和验收阶段见[研发方向](voice-runtime-direction.md)与[里程碑](voice-runtime-roadmap.json)及[完整V1验收合同](voice-runtime-v1-acceptance.md)。目标值不是已测性能，也不表示完整 AI 链路已经实现。

## 运行总览修复

压力测试运行在独立实例，原总览只读取主服务状态，因而看不到压测呼叫。本轮在总览增加独立测试数据源：实际活动/接通呼叫、RTP计数、worker和控制进程CPU/RSS、最近样本趋势与采样时间。主服务和压测数据分别显示，不将目标并发当成实际呼叫数。

轮询失败、无样本和超过10秒的旧样本明确显示；切换任务、服务重启和离开页面不会继续显示旧任务实时状态。测试结束后显示最近一次结果及其时间。[总览观测合同](overview-testing-reference.md)记录字段来源与采样限制。

## 本轮实现

- `uuid_send_dtmf`：已ACK本地A腿发送协商的RTP telephone-event；真实受理、完成、失败、队列上限和挂机清理分别验证。透明桥接/B腿/INFO发送仍明确拒绝。`uuid_send_dtmf_status`是自有扩展；内部新增两项IPC，不能把这三项当成原版新增兼容命令。[完整按键发送合同](dtmf-send-reference.md)。
- AudioFrame支持8/16/24/48k、单声道10/20ms与来源时间；同采样率分支移动现有缓冲，需转换的分支才运行离线参考重采样。G.711/G.722/Opus可按原生采样率解码，旧16k入口保留。这仍是离线SDK，未接入实时通话AudioGraph或ASR/TTS。[音频帧合同](audio-frame-reference.md)。
- 对照待办新增首期范围和优先级，保留全部原始ID与未完成状态；视频、会议、传真和原模块宿主延后，未删除或标为通过。

## 原版按键差异与下一步

双方对 `12#@100` 实际收到21个PT101事件包，时长800个8k刻度、每数字三个结束包。共同播放1600ms提示音时，原版收到74个音频包，候选80个；原版按键期间存在800刻度音频时间戳间隔，候选维持160刻度节奏。该差异写入成对报告，不将这一个场景外推为整体性能更优。[13组原版业务对照](ai-calling-verification-v1.9.md)。

首期剩余重点是实时AudioGraph、流式ASR/TTS、turn_id取消和发送前校验、双轨录音、实际线路转人工以及对应安全与背压。离线SDK和受限播放器不代替这些能力。本轮没有5000/10000路完整Agent组合的新通过证据，原容量失败继续保留；1.5倍并发、CPU/内存下降30%、尾延迟及72小时均仍是目标。
