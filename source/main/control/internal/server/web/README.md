# RustSwitch 中文管理页面

本说明按 1.12 文档合同维护；实际部署版本由 `GET /v1/docs` 返回的 `version` 核对。该目录由 Go 管理服务内嵌提供，直接使用同源管理 API，不依赖 CDN、前端打包器或第三方组件。`index.html` 提供页面框架，`app.css` 管理响应式样式，`app.js` 管理数据、表单、状态采样与提交。需要支持 Fetch、原生 dialog、DOMParser 和现代 JavaScript 的浏览器。

## 页面与生效范围

| 页面 | 提供的操作 | 生效范围 |
| --- | --- | --- |
| 运行总览 | 主服务趋势、媒体分片、准入健康及独立压测实例的实际样本/处理帧 | 每 3 秒分别读取状态与测试目录；后台标签页暂停定时采集，两个实例不混合 |
| 峰值保护 | 总并发、建立中、每秒速率、突发桶、柔性降速、重试间隔 | 策略保存立即生效；受当前启动硬上限限制 |
| SIP 与媒体 | 地址、CIDR、超时、端口、进程、缓冲、CPU 绑定与媒体压力门限 | 保存待重启；显示当前有效值与本地差异 |
| 运维配置 | 管理地址、日志队列、日志健康、排空与恢复、配置快照 | 配置待重启；排空与恢复即时执行 |
| 压力与电话测试 | 指定并发与速率、单路小电话、任务恢复、停止、双向报告、历史下载 | 显式创建本机独立测试，不代表生产容量认证 |
| FreeSWITCH 配置 | 分类、搜索、文件筛选、批量条目编辑、XML、新增用户/网关/路由、ZIP 导出 | 此页保存的是导出草稿；部署级 sip.dialplan 已支持单独的受限 XML 顺序运行，不从本页自动热加载 |
| 兼容能力 | 服务端返回的模块与功能支持状态 | 不计算未经认证的兼容完成比例 |
| 音频编解码 | 实际 codec 目录、主服务模式及当前 Worker 处理能力 | 原生 SDK 探测与实时 G.711 就绪分开，握手就绪不是实际通话通过 |
| 接口文档 | HTTP 操作、文档、Schema、原文和完整下载包 | 只读，示例不执行；PCM/RVA1 是独立二进制协议，不新增音频 HTTP 入口 |
| FreeSWITCH 对照 | 双方语义、实现状态、本地证据与原版成对差异 | 实现、限定本地通过、原版差异分开，不能用条目数推导完整兼容率 |

保护页的 8,000 是 `max_active_calls`：同时占用或预留资源的呼叫数；1,000 是 `max_establishing_calls`：尚未建立或仍等待释放的资源数。后者按 active−established 计，不是“已接通并发上限”，也不是每秒 1,000 次新呼叫。`calls_per_second` 才是次/秒，`burst_calls` 是令牌突发预算；建议策略可能同时填写数值 1,000，但字段、单位和触发条件必须独立展示。

建议按钮只填写本地策略，并按当前启动上限收缩；保存后才生效。启动级容量草稿另行保存，改变硬上限仍需重启。柔性降速作用于新呼叫准入，不延迟已有通话的 ACK 或媒体。端口预算只反映资源约束，不是万路性能验收结果。

媒体程序路径 `media.binary`、日志路径 `journal.path`、拨号计划 `sip.dialplan` 与 PCM 入口 `pcm_stream` 等部署字段由服务端限制为只读；完整配置 PUT 必须保留原值，不能由页面热换。浏览器检查数字范围、IPv4 CIDR、端口容量、CPU 绑定数量等；地址安全、平台约束、路径策略和最终配置合法性由服务端继续校验。

## 主服务与独立测试的数据来源

主服务取 `GET /v1/status`；压测区域取 `GET /v1/tests` 响应的 current/history，并按任务读取 `GET /v1/tests/{id}`。`current` 是响应字段，不是 `/v1/tests.current` 路由。压测使用另外的控制进程、Rust Worker 与发生器；主服务显示 0 路、隔离测试显示 500 路可以同时成立，不将两者曲线、CPU、帧数或健康状态相加。

任务目标 concurrency 和发生器累计 established_calls 都不能替代子实例实时 active_calls/established_calls。g711 实际处理帧来自任务 `sample.processing`，relay 不填造解码/编码数。主服务本地 consumed/nonzero/energy 只描述 RX，不把外部 PCM TX 样本加进来。缺 worker、坏字段或过期样本显示未知/过期，HTTP 请求刚成功也不能证明内部样本新鲜。历史终态样本不是当前在线负载；任务完成标签不代替完整媒体及清理验收。详见 [总览观测合同](../../../../docs/api/overview-testing-reference.md)。

## XML 运行与草稿边界

FreeSWITCH 配置页继续保存、编辑和导出草稿，不自动写入部署拨号计划或触发 reloadxml。引擎已支持部署级 `sip.dialplan.file/context` 指定的受限单文件 XML：启动时严格读取和编译一次，按受支持条件匹配本地路由及顺序动作，未命中返回 404；合法 ACK 后才执行应用。支持范围和未知元素/参数拒绝规则见 [XML 拨号计划](../../../../docs/api/dialplan-reference.md)。

完整原版 XML 配置树、动态 include/XML Curl、Lua、全部 Dialplan 和热加载没有因此完成。网页 XML 保存成功、ZIP 导出成功和实际通话执行是三个不同结果。

## 数据与提交契约

- 初次从 `GET /v1/config` 取得有效配置、待重启配置、保护策略、共享版本和 CSRF token；运行状态来自 `GET /v1/status`。
- 所有 `PUT` / `POST` 都使用同源 JSON 与 `X-RustSwitch-CSRF`。配置、保护、FreeSWITCH 参数和 XML 共用服务端递增版本，分别保留它们被读取时的本地基准版本。
- `PUT /v1/config` 提交完整待重启配置；`PUT /v1/guard` 只提交完整保护策略。提交期间锁定编辑入口，防止响应覆盖新输入。
- `PUT /v1/fs-config` 提交本次修改的 `overrides`；目录里的 `parameters.value` 是已保存取值。XML 结构变化后重新读取条目目录。
- `GET` / `PUT /v1/fs-config/file` 管理单份 XML 文本；支持相对路径内的新 `.xml` 文件。浏览器生成的用户、Sofia 网关和拨号计划均先成为本地草稿，经过人工查看和保存后才能进入导出包。
- `GET /v1/fs-config/export` 下载已保存的配置树。未保存参数或 XML 时会提示先保存或撤销，防止误以为导出包含本地输入。

运行轮询不会替换配置表单、提升草稿版本或丢弃本地输入。自己的保存成功后，只推进同一旧版本的其他本地状态；原本已经过期的草稿仍然保留旧版本。收到 `409` 时提供“导出本地草稿”和“重新载入最新配置”，不会自动重试覆盖。重新载入前，明确确认是否放弃本地修改。

参数表单与 XML 结构编辑不能在尚有未保存修改时互相切换；不同 XML 文件的本地草稿按路径保留。XML 保存之后的目录读取若发现额外版本变化，仍保持保存响应的基准版本并提示冲突。

## 状态说明

当前限流依据 `guard.limit_reason` 与 `guard.throttled`；`last_reject_reason` 仅标记为历史记录。媒体分片原因包含 `stale_media_stats`、`media_drops`、`media_cpu` 等服务端字段。累计丢失事件与当前异常分开描述。

接口没有提供原始服务日志。页面的“日志与观察”仅显示真实计数和本次浏览器观察到的状态变化，刷新后清空，不冒充完整审计日志。离线时保留最后成功采样并明显标记数据未更新。趋势仅反映当前浏览器取得的样本。

## 验证边界

早期版本记录的 JavaScript 语法检查与 16 项隔离逻辑检查，涵盖转义、CIDR、资源容量、共享版本推进、历史拒绝与当前限流区分、XML 路径以及原生确认对话框提交保留。它们使用 DOM 桩，不能覆盖后来增加的全部功能或替代当前浏览器交互验证；当前执行范围以 [1.12 验证记录](../../../../docs/api/release-validation-v1.12.md) 和具体回执为准。

浏览器交互应覆盖：导航与窄屏菜单、编辑期间轮询、保护保存、待重启配置差异、409 保留、离线恢复、参数搜索与批量保存、XML 新增/保存/导出、排空/恢复确认。完整性能和 FreeSWITCH 无感替换认证仍需独立执行项目验收。

## 接口文档与 FreeSWITCH 对照

新增两个独立只读页面：`#api-docs` 和 `#fs-comparison`。`docs.js` 在 `app.js` 前加载，向主页面暴露 `RustSwitchDocs.mount(page)` / `leave()`；`docs.css` 复用管理台配色并增加长文、Schema 树、目录和双栏对照样式。后端已注册 `/docs.js`、`/docs.css`；文档包更新后仍需重新构建并实际部署。

文档只使用 `GET /v1/docs`、`/v1/docs/openapi.json`、`/v1/docs/comparison.json`、`/v1/docs/file?path=…` 与 `/v1/docs/export.zip`，没有测试请求、在线调用或自动写入接口。JSON/cURL 示例仅复制；示例中的 token、版本和业务值必须由操作者核对填写。

接口文档提供 HTTP 操作、章节文档和数据结构三个入口。路径公共参数与操作参数合并后展示，递归展开本地 `$ref`、属性、数组、组合条件、枚举与其他约束；全部请求体、响应状态和原始对象可查看。递归循环明确终止并链接到结构定义，超过默认深度可按需继续展开。搜索索引包含被引用结构的字段名。章节支持安全 Markdown、JSON 格式化、CSV 前 100 行预览和完整原文，以及 C 头文件等文本。

Markdown 原始 HTML 一律转义，图片不内嵌执行。相对链接按当前文档路径归一化，只有命中 manifest 的文件能在页面内跳转；未收录的 Go/Rust 源码引用显示为文字，不猜测可用地址。外部 URL 限定明确的官方来源域或 SignalWire FreeSWITCH 仓库；拒绝其他协议与用户凭据 URL。源文件下载同样限定索引路径。

FreeSWITCH 对照搜索覆盖全量记录，并可按分类、状态筛选，每页只渲染 12 条。每条显示两侧接口与语义，展开后展示完整差异、验证、源位置、官方链接及语义文档。原始条目和完整 JSON/ZIP 可下载；目录计数不解释为兼容通过率。代码复制缓存只保留当前页和页头数据，避免浏览大量分页后持续累积。

页面内状态编码在 hash 查询参数中，支持 operation、document/anchor、schema、搜索、分类、状态、页码和指定对照条目直达。运行轮询不会重绘文档；导航和正文读取分别用请求代次检查，迟到响应只允许进入缓存，不能覆盖新的页面。搜索采用短防抖且支持中文输入法，不重建搜索框。读取失败可显式重试。

新增文档逻辑已通过 JavaScript 语法检查，以及基于实际 OpenAPI 的操作/Schema 渲染、HTML/URL 安全、相对路径、循环引用与万条合成对照分页等隔离检查。实际浏览器布局、下载和交互仍由主任务联调确认。

对照中的 `implemented` 显示为“自有接口已实现”，仅说明 RustSwitch 对应的自有入口已实现，包括独立管理或 PCM 协议，不能推导 FreeSWITCH 报文兼容。对应关系枚举使用中文说明“用途相近但报文不兼容”“仅配置产物”“无兼容入口”等边界，未知枚举保留原文。

## 压力与电话测试

`#tests` 由独立的 `tests.js` / `tests.css` 提供，通过 `RustSwitchTests.mount({request})` 与 `leave()` 接入管理框架。压力模拟支持 500、1,000、2,000、3,000、5,000 路预设，以及 1—10,000 路自定义；建立速率为 1—1,000 次/秒、媒体持续时间为 1—300 秒，最终范围还受服务端能力限制。默认表单值不触发测试。

测试小电话固定一条 SIP 会话、每秒一次建立，按后端能力目录选择格式、处理模式与媒体保持时间。拨号后使用发生器发送并核对双向 RTP，不调用麦克风、不拨打真实外部号码；挂断属于显式停止，不作为完整通过。两个模式均使用真实独立控制实例、Rust 媒体进程和发生器。它们与管理服务共用本机 CPU 和网卡，采用隔离容量模式，保留启动硬限制和媒体健康准入；不能将同机结果解释为生产万路认证。

此页使用 `GET /v1/tests`、`POST /v1/tests`、`GET /v1/tests/{id}`、`POST /v1/tests/{id}/stop`、`GET /v1/tests/{id}/report`。创建使用 `mode=pressure` 或 `phone`；`media_processing` 显式选择 relay/g711，缺省 relay，不继承主服务模式。relay 的 payload 从实际测试能力目录选取；g711 只允许 0/8，并实际让两腿使用相反 G.711 编码以验证处理；写操作复用主页面同源 JSON/CSRF 适配器。每次逻辑任务生成唯一 `request_id`，提交期间及已有运行任务时禁止重开。创建超时保留原始请求参数与标识到当前浏览器会话存储，允许显式重试同一请求；不会自动生成第二个任务。

页面进入时读取后台当前任务与最多 20 条历史摘要，随后读取所选任务详情。离开页面只取消前端轮询，不发送停止请求；重新进入或浏览器刷新后恢复后台真实状态。运行中约每秒读取，闲置约每 4 秒读取，后台标签页降低到 5 秒；代次检查防止旧请求覆盖新的任务选择。实时刷新不重建参数表单，报告缓存按当前任务和最近历史剪枝，详情展开与日志阅读位置保留。

实际活跃和已接通通话来自子实例状态样本；发生器 `progress.established_calls` 显示为累计通过建立验证数，不能当作拆线后的活跃数。样本保留窗口峰值与最终证据中的全程采样峰值分开命名；日志记录的接通峰值单独展示。子实例媒体接收/发送计数之差不能推断端到端丢包：只有最终发生器报告中的 `unreceived_packets` 才显示为未接收包，尚无数据时显示“—”。报告另按两个方向展示发送、唯一接收、缺包通话数和单通话接收包范围。套接字丢弃计数依赖平台支持，平台未提供该计数时零值不能证明无丢包。

当前负载模型先建立所有通话，再发送媒体，最后统一拆线，媒体持续时间不含建立和清理。这不覆盖持续建拆负载。最终通过提示要求后台任务完成、发生器 `passed=true` 且清理完成；预检失败、提前停止、缺少报告或清理失败均保留各自真实状态。平台不支持、缺二进制、端口不足、进程失败等后端错误直接显示；报告下载也保留失败原因、预检证据和日志尾部，不生成替代成功数据。

新增测试模块须验证：两个模式参数校验、当前任务恢复、重复点击及创建超时后的同键重试、停止与清理、最终报告空结果、历史查看、读取失败恢复、离开页面不停止、轮询不覆盖参数、手机布局与下载。单机容量结论仍以真实运行证据为准。

早期测试模块记录了主入口 JavaScript 语法检查及 29 项隔离逻辑检查，覆盖范围校验、空样本与峰值来源、建立错误计数、双向展示、报告成功边界、日志转义、重复点击、迟到创建响应、同键重试及离页不停止。这些检查没有启动真实 SIP 或压力任务，不能替代浏览器与真实呼叫验收。

## PCM 端点属于部署配置

`pcm_stream` 省略/null 时关闭；启用须由受控启动配置提供私有 Unix socket 路径。`socket_path`、`max_connections`、`max_streams` 整个节点在管理 PUT 中都只读；即使用户修改浏览器对象，服务端也不能接受热启停或额度变更。独立 testlab 配置不继承主服务 PCM 端点，不能争用业务 socket。

外部 RVA1 连接面向同 UID 可信进程，使用私有父目录与 0600 socket、固定控制/数据连接预算；BEGIN 必须经主循环授权已 ACK 的本地 G.711 A 腿 UUID。页面不是麦克风、远程租户授权或每 20ms HTTP JSON 供音入口。PCM 与活动或排队的提示音互斥，静默 read/park 可并存；`uuid_break` 不自动取消 PCM，明确 INTERRUPT 才控制轮次。完整字段、0/20/40ms 淡出、未知结果恢复与未完成的 ASR/TTS/VAD/录音见 [RVA1](../../../../docs/api/rva1-reference.md) 和 [内部 PCM](../../../../docs/api/pcm-turn-reference.md)。

本文维护说明不授予新压力成绩或页面部署成功。绿色由实际源绑定证据决定，旧 500/5000 路失败不能因改文档、换显示方式或功能单测通过而消失。
