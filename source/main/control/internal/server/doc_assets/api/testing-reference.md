# 压力模拟与测试小电话接口

管理后台创建、停止和完整报告入口为 `/#tests`；`/#overview` 同时展示正在运行或最近一次隔离测试的真实采样，并把主服务状态另列。数据来源、CPU/RSS口径和过期规则见[运行总览与隔离测试观测](overview-testing-reference.md)。压力档位为 500、1,000、2,000、3,000、5,000 与自定义 1–10,000 路；测试小电话固定为单路。压力和单路模式都实际执行 SIP 建立、双向 RTP 与拆线。媒体另可选择同编码透传或 G.711 双腿解码/编码处理。测试小电话不使用浏览器麦克风、不注册真实分机、不拨打外部号码。

## 测试边界

服务启动一个专用的控制进程、Rust 媒体进程和 `callbench` 发生器，并使用独立配置、日志和端口。地址只来自本机回环探测，浏览器不能提交任意目标、命令、程序或磁盘路径。测试不修改当前业务服务的运行参数、FreeSWITCH 配置草稿或峰值保护策略。

测试实例按请求的目标容量配置自己的硬上限，关闭该实例额外的业务峰值软限制，并保留媒体健康准入。该模式用于观察请求规模的实际结果，不是对生产实例的压力注入，也不表示验证了生产环境现有保护阈值。同机发生器和服务共享 CPU、内存与网络栈，测试期间仍会增加服务器负载。

Linux 优先使用可绑定的独立回环地址；不修改系统网络配置。不能使用独立地址时，在同一回环地址上排除当前服务声明的媒体范围和信令端口。无法取得足够端口、文件描述符或测试程序时，返回实际失败原因，不能缩小并发后仍把原目标记为通过。

遇到其他本机程序已占用的端口，执行器排除该端口并重新规划，最多尝试 128 次；不终止其他程序。`resource_preflight.port_replans` 记录重新规划次数，`excluded_busy_ports` 记录已排除端口。每次仍按原并发目标计算完整媒体区间，并允许区间内跳过受保护或繁忙的四端口块；各分片独立核算容量。

高并发发生器使用有限数量的共享端点套接字。透传按来源、SSRC及本地socket区分呼叫；g711按协商的媒体来源及本地socket识别新输出流，最多32组、64个RTP读者。完整报告保留实际套接字组数。这会减少发生器自身端口和文件描述符消耗，不等同于数千个独立物理终端的资源布局。真实网卡、独立发生器、长时间稳定性及万路生产容量仍须单独验收。

## API 与调用顺序

| 方法与路径 | 作用 |
| --- | --- |
| `GET /v1/tests` | 读取运行能力、当前任务与最近任务摘要 |
| `POST /v1/tests` | 校验并启动压力或单路测试 |
| `GET /v1/tests/{id}` | 读取指定任务进度、样本及清理状态 |
| `POST /v1/tests/{id}/stop` | 停止指定任务，只清理它拥有的进程和资源 |
| `GET /v1/tests/{id}/report` | 下载已结束任务的完整结果与有界日志尾部 |

所有操作使用现有回环 HTTP 管理边界。POST 使用 `Content-Type: application/json` 和 `X-RustSwitch-CSRF`，令牌从 `GET /v1/config.csrf_token` 取得。测试作业使用 `request_id` 去重，不使用配置 `revision`，也不会推进配置版本。

创建参数：

| 字段 | 含义及范围 |
| --- | --- |
| `request_id` | 客户端为一次创建生成的唯一键；1–128 字符，首字符为字母或数字，其余可用字母、数字及 `_ . : -`；网络结果不确定时保留此键核查或重试 |
| `mode` | `pressure` 为压力测试；`phone` 为单路测试 |
| `media_processing` | `relay` 同格式透传或 `g711` 双腿异律处理；省略/空值规范为relay，独立于主服务配置；g711只接受payload 0或8 |
| `concurrency` | 目标同时建立的桥接通话数，1–10,000；phone 固定为 1 |
| `cps` | 新呼叫发起速率，1–1,000 次/秒，与同时并发数量不同 |
| `duration_seconds` | 全部拨号完成后的媒体发送时长，1–300 秒；不包括启动、建立和清理时间 |
| `payload` | 固定20ms音频预设；G.711/G722/Opus/G729/G726/AAL2/L16，完整PT映射见 [音频接口](audio-reference.md) |

单路示例正文：

```json
{
  "request_id": "phone-example-20260905-001",
  "mode": "phone",
  "concurrency": 1,
  "cps": 1,
  "duration_seconds": 5,
  "payload": 0
}
```

500 路示例正文：

```json
{
  "request_id": "pressure-example-20260905-001",
  "mode": "pressure",
  "concurrency": 500,
  "cps": 100,
  "duration_seconds": 10,
  "payload": 0
}
```

示例只用于说明，不会由文档页面自动执行。同一个 `request_id` 配合相同参数返回原任务，参数不同时返回 409；另一个测试尚未结束时也返回 409。创建的 202 只表示任务已经受理，资源预检、启动或真实通话仍可能失败。

取回创建响应中的 `id` 后轮询任务状态；离开页面或关闭浏览器不会自动取消任务，重新进入页面可恢复查看。挂断/停止使用该 ID 提交 `{}`，进入停止过程后继续查看，直到任务终态和清理结果均明确。

执行上下文的总期限为 `ceil(concurrency / cps) + duration_seconds + 90` 秒，包括独立实例启动、建立、媒体与结果收敛；到期进入失败清理，清理和报告发布可能晚于该期限。主服务开始退出时立即取消自己的测试任务，并等待专属子进程清理。

报告只保留在当前控制进程内存中，最近 20 份可下载，重启后清空；需要留档时应及时下载。每份报告最多保留最近 300 个成功统计样本，两个程序各保留最近 64 KiB 日志，全程采样峰值单独记录。幂等键最多保留 4,096 条；报告淘汰后原键返回 410，不重新运行；达到键数上限返回 429。清理证据不完整时冻结新增任务入口，并在目录中返回具体原因。

## 结果判读

文档 1.2.0 在 `samples[].controller` 和 `evidence.final_status.controller` 增加测试 Go 控制进程的资源与队列观测；旧报告可能没有这些字段。CPU 核数、Go 协程和运行时存活线程分别命名，不能互相替代；无可用观测时为空值。主服务自身的相同观测位于 `GET /v1/status.controller`，不会混入测试结果。

任务状态区分准备、运行、停止中、完成、失败和已停止；阶段区分预检、拨号、媒体、拆线和结束。页面进度来自发生器的原子快照和测试实例的真实统计，缺失的观测不能当作零缺包或已经接通。

运行总览读取同一组子实例样本，不只观察主服务 `/v1/status`。因此主服务空闲时显示0路，不妨碍独立测试区域显示实际压测并发。总览保留样本内峰值、主服务曲线和最终报告的全程峰值使用不同口径；完整判定仍以本页所述报告和清理证据为准。

`requested_calls` 为请求目标；`established_calls` 为发生器完成建立的数量，不能单独证明同一时刻都在线。应同时核对服务峰值样本/生命周期证据。`sent_packets` 为发生器 UDP 完整写入的报文数量；`received_unique_packets` 为模拟端点校验后的唯一报文数量；`unreceived_packets` 是各通话方向发送减唯一接收的正差之和，不能仅据此判断是哪一跳丢包。

发生器通过要求完整接通、总量及每路每方向的标称负载至少达到 98%、无缺包/重复/非法包/发送或接收错误/意外拆线/拆线失败。总体结果还需结合服务与媒体资源释放、日志证据和清理状态。`cleanup.complete=false` 时不能把任务作为成功测试。人工停止不代表通过，运行失败也应能查看已取得的观测与失败日志。全局发送量合格不能代替逐通话检查，例如 4900 路发足、100 路没有发送的 5000 路任务仍必须失败。

任务报告保留实际配置边界、调用参数、运行阶段、发送/接收统计、方向明细、发生器自身资源、失败原因和清理结果。端口不足、发生器未完成、采样不足或报告缺失均应明确保留，不生成假结果或假的容量结论。

`result.directions` 分别列出两个媒体方向的发送、接收、存在缺包的通话数，以及每路接收包数范围。`setup_errors` 是“失败原因到次数”的对象。`setup_cps` 是目标发起速率；需要实际平均建立成功速率时，使用 `established_calls / setup_seconds`，不能把目标值当成实测值。

`evidence.peak_sampled_established_calls` 是全程成功 HTTP 采样的最大同时接通数，短瞬间可能被采样间隔遗漏；`journal_peak_established_calls` 使用同一测试实例的建立/结束事件计算并发峰值。CPU 和峰值内存样本只汇总 Rust 媒体进程，其中内存是各进程自身峰值之和；发生器资源另见 `result.generator_resources`。内核接收丢包统计受操作系统支持限制，显示 0 不能独立证明网络没有丢包。

## FreeSWITCH 对应说明

这些 `/v1/tests` 路由是本项目自有测试管理接口，FreeSWITCH 没有同名 HTTP 测试作业合同。原版 `originate` 负责发起其自身通道，`status`/`show channels` 负责观测，不等同于本页同时管理主叫、被叫、真实 RTP 校验和隔离实例清理的生命周期。

本测试不能验证原版 ESL、XML 拨号计划、原生模块加载、会议、录音、转码或故障状态迁移。结果不填充已有 FreeSWITCH 差分认证为通过；可用作当前 RustSwitch 受限 SIP 与媒体能力的独立测试证据。

完整可机读参数、任务结构及全部错误状态以 [OpenAPI](openapi.json) 中的“压力与电话测试”操作为准；媒体和 CLI 行为另见 [非 HTTP 接口](protocol-reference.md)。

## 自动化验收工具

从项目根目录构建 `make all` 并启动管理服务后，可运行以下单路功能验收。工具只连接显式指定的回环 HTTP 管理地址；已有测试运行时退出，不停止他人的任务。输出为不含管理令牌和配置正文的摘要。

```sh
python3 tests/testlab_e2e.py --url http://127.0.0.1:9080 --output /tmp/rustswitch-testlab-phone.json
```

默认验证非法请求拒绝、同键幂等、单路 SIP / 双向 RTP、媒体阶段停止及资源清理。只有增加 `--pressure-calls` 才执行并发负载，例如：

```sh
python3 tests/testlab_e2e.py --url http://127.0.0.1:9080 --pressure-calls 500 --pressure-cps 100 --seconds 10 --output /tmp/rustswitch-testlab-500.json
```

端口或性能不足时工具返回非零退出码并保留实际摘要。此工具验收当前功能，不代替目标 Linux 服务器上的独立发生器、真实网卡与长时间容量验收。

## 1.3 端口预检与失败分类

`capabilities.port_capacity` 是回退地址、CPS1000的保守端口模型，不是实测容量。任务报告 `resource_preflight.port_capacity` 使用本次实际并发和CPS；`verified=true` 仅证明 `verified_concurrency` 所指请求已完成全部端口预留，`max_concurrency/available_presets` 仍是规划估计。

端口不足时 `failure={stage:preflight,code:port_capacity,processes_started:false,message,capacity}` 明确记录未启动。此路径没有发生器结果，页面显示“预检未启动”，不再同时误报媒体核对失败。报告也在 `evidence.failure` 保留原因。其他预检失败保留相应原因码；未分类旧记录不应按中文文本猜测。

同址主媒体10000–64999时，可用地址空间有硬边界；碎片优化不能让3000/5000路自动获得不存在的四端口资源。程序保留主服务当前及待启动媒体范围，逐块跳过保护端口与实际占用，真实分片分配仍须成功。编排器预留阶段也计入FD预算，临时探测不会无限消耗主进程资源。

测试报告新增 `result.codec` 和 `validation_scope`。G729/G726使用结构测试码字，包相等不表示主观语音质量合格。所有格式均验证按自身RTP时钟推进的序列，不再假设每20ms时间戳增加160。

## 1.4 发生器调度与实际验证记录

Linux amd64/arm64 的发生器通过 `sendmmsg/recvmmsg` 在同一端点一次最多处理 32 个报文。每个共享端点固定由一个发送者负责；发送计划和缓冲区在媒体计时前准备。迟到的发送相位有最小追赶间隔，仍保持原来的 20ms 包时长、固定媒体截止时间和完整名义包数，不能通过延长测试或删除计划包来获得通过。

`generator_io_mode` 区分 `linux_mmsg` 和 `portable_udp`。`generator_send_calls/receive_calls` 在 Linux 批量路径计入实际系统调用尝试，包括暂不可读写和被信号中断的尝试；便携路径统计标准库 UDP API 调用，不能称为等量内核调用。具体计数边界由 `generator_io_count_boundary` 明示。`generator_sender_workers` 是实际拥有发送计划的工作者数。

`generator_reader_errors` 记录提前读超时或其他接收退出，非零使测试失败；发送全部结束后，正常尾部等待超时另记为 `generator_reader_timeouts`。拆线并行度最多 64，保留每路拆线响应与失败结果，避免一次创建数千个拆线协程。

对照页的绿色状态由[本地运行验证证据](runtime-verification.md)决定，绑定实际日志、二进制和运行前后源码。代码变化、证据损坏或超过复查期限时不再标绿。5000 路场景通过与原对照中的万路目标分别保留；本地测试不会自动升级成原版 FreeSWITCH 成对认证。

`underloaded_flow_directions` 为媒体发送或接收不足的通话方向数，`directions[].underloaded_flows/minimum_sent_per_flow` 定位单向负载缺口。`unexpected_received_packets` 单独记录逐方向超出实际发送的唯一接收数，不能与其他方向缺包互相抵消。任一项非零使本次发生器验收失败。

## 1.6 任务读取与重启恢复

测试目录和报告仍只在内存保留。页面每次以成功读取的 `/v1/tests` 目录判断当前选择是否仍存在；服务重启或历史淘汰后自动取消失效选择，展示当前任务或空列表，并保留尚未提交的输入。目录与详情读取之间发生404/410时，只清理失效记录。详情503或临时报告失败单独显示并在后续轮询恢复，不把整个主服务标记离线。

写请求遇到服务明确返回403及 `X-RustSwitch-CSRF-Refresh: required` 时，页面读取新令牌并只重试一次原请求，保留原幂等键和正文；普通403、版本冲突或网络结果未知不会自动重放。重启清空任务记录和幂等索引，因此没有跨进程任务恢复承诺。

对应回归为 `tools/test_testlab_ui.cjs` 的11种轮询场景和 `tools/test_admin_request_ui.cjs` 的8种令牌/写入场景；实际页面重启与真实电话/压力测试另见[本轮验证记录](release-validation-v1.6.md)。

## G.711 处理与严格报告（1.10）

处理模式的格式协商、全部160个PCM样本校验、固定期限、有限PLC、拆线后新鲜统计和有界首错见[真实处理压测合同](processed-testing-reference.md)。未知统计与实际失败分别记录，不能用旧报告的 `passed` 布尔值补全处理证据。
