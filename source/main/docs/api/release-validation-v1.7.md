# RustSwitch 1.7 缺口实现与逐项验证

本轮已补齐 AI 电话链中一组可实际使用的缺口：受限 XML 拨号计划、answer/sleep/park/hangup、真实 WAV 放音、播放终止键、普通 uuid_break、批量变量和标准普通事件名称订阅。全部新增代码按中文说明维护。参考仍固定 FreeSWITCH 1.11.3；以下证据不表示全模块、全部协议或万路容量已完成。

## 本轮实现

| 入口 | 实际行为 | 主要边界 |
|---|---|---|
| `sip.dialplan` | 启动冻结 XML；指定context按号码匹配，顺序执行八个限定应用，未匹配404 | 无完整条件求值、预处理、动态重载、bridge或变量展开；后台导出草稿不自动运行 |
| `answer/sleep/park/hangup` | 真实媒体准备后接听、等待ACK、定时顺序执行、保持停泊及实际BYE | park私有事件抢占、全部cause和完整会话状态仍未实现 |
| WAV文件播放 | 8k单声道PCM16/PCMA/PCMU文件，向当前PCMA/PCMU腿发送实际RTP | 相对受控root、1MiB/30秒、异步有界加载；无任意文件后端、URL或实时重采样 |
| 播放终止／`uuid_break` | 默认*、none、自定义按键、真实停音后完成；read仅停止提示音后继续收号 | 原版FILE PLAYED也用于主动中断，不能推断完整播放；all/both、纯等待数字的read打断未兼容 |
| `uuid_setvar_multi` | 批量变量真实读回、空值和缺等号删除、引号／转义／有限自定义分隔、部分成功 | 64项/16KiB批次预算；无完整变量展开、数组和全部变量副作用 |
| ESL普通名称订阅 | 固定目录92个普通事件名称可订阅，客户端混合订阅不再整体失败 | CUSTOM子类仍未实现；订阅成功不合成不存在的业务事件 |

文件加载使用固定线程与有界队列／缓存。停止、挂机和会话复用后，迟到加载结果不能恢复旧播放；加载失败不会继续 XML 后续动作。XML 关闭 ESL 时也能实际收号和挂机，内部通道身份不再依赖外部事件发布器。部署的 XML 路径、context、放音root在后台只读，完整配置PUT须保持原值。

## 绿色状态与剩余工作

对照目录现为3985条：882仅配置导出、17自有入口、11内部接口、2851未实现、178未验证、46部分实现。本地绿色54条，全部限定到已执行断言；3930条未执行，容量项保持失败。目录条数与绿色条数都不是FreeSWITCH兼容率。

本轮仍观察到5处场景的生命周期事件不一致：三种放音场景缺完整PLAYBACK_START/STOP，两个XML停泊场景缺完整CHANNEL_PARK/UNPARK。相应完整事件合同继续保留缺口。

仍需实现及逐项对测：终端REGISTER服务器与位置数据库、多网关、originate／动态bridge／transfer／re-INVITE、完整XML菜单／条件与变量展开、outbound ESL、完整事件生命周期、通话录音与会议、实时ASR／TTS／AudioGraph、通话转码、WebRTC／SRTP／DTLS／ICE及其他端点协议。它们不能通过声明目录齐全或已有同名配置替代运行实现。

本轮没有新的5000或10000并发认证。1.5最近一次5000路失败记录保留，1.4历史成功不继承为当前绿色。单路对照、500路页面回归和万路业务组合必须分别验收；后续物理Linux服务器仍需测足量双向媒体、实际网卡丢包、CPU／线程、故障和完整回收。

接口细节见 [XML与基础应用](dialplan-reference.md)、[WAV文件](file-playback-reference.md)、[批量变量](variables-reference.md)、[ESL](esl-reference.md) 与 [完整对照表](freeswitch-comparison.md)。
