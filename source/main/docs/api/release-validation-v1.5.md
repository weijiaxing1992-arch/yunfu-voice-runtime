# RustSwitch 1.5 开发交付与验证说明

本轮补齐了有限 ESL 控制入口和 SIP TCP/TLS 传输，并实际运行 FreeSWITCH 1.11.3 做成对比较。**当前仍未达到 FreeSWITCH 100% 兼容；本轮新构建也未通过 5000 路容量验收。** 后台绿色只表示证据中明确列出的子场景通过，不能扩大为模块、协议或整机能力认证。

本文记录 2026-09-06 的实际结果。原始对照固定为 FreeSWITCH 1.11.3，提交 `ef32e205295e29f034f1453ad245ba5efb07b94a`，保留 3979 个原条目，完整契约通过数为 0。不会删除未实现项目、缩小分母或用入口发现替代功能验证。

## 本轮已开发内容

### 有限 ESL 控制与事件

新增独立、可选的 ESL 监听，默认不启用。产品通过 `-esl-password-file` 读取私有普通密码文件；成对测试执行器另用专用环境变量传入隔离测试凭据。启动、连接、认证、消息长度、队列和后台作业均有资源边界。支持 `api`、`bgapi`、原版 `fs_cli -x` 的单 API 控制台包装、事件订阅和基础筛选，以及 plain、JSON、XML 事件格式的已测试子集。

当前运行目录暴露以下 9 个 API 入口：

| API | 已实现范围 |
|---|---|
| `echo` | 回显正文，按实际字节数生成 Content-Length |
| `create_uuid` | 生成标准 UUID |
| `version` | 返回 RustSwitch 真实产品身份，不伪装原版 |
| `status` | 返回 RustSwitch 当前运行摘要，非原版全字段格式 |
| `show api as json` | 列出当前 9 个入口；其他 show 子命令明确失败 |
| `uuid_exists` | 查询当前通话腿是否存在 |
| `uuid_getvar` | 读取已实现的基础通道变量 |
| `uuid_setvar` | 修改基础变量；复杂展开、数组语义仍有缺口 |
| `uuid_kill` | 对真实通话执行正常挂机；非全部挂断原因映射 |

事件子集为 `BACKGROUND_JOB`、`CHANNEL_CREATE`、`CHANNEL_ANSWER`、`CHANNEL_HANGUP`。通话事件来自真实生命周期；UUID 索引由呼叫主循环维护，管理命令不会跨线程扫描、修改通话状态。完整 FreeSWITCH 事件字段、应用事件、出站 ESL 和所有命令语义仍未完成。

补测原版客户端时，曾发现 `fs_cli -x` 的 `console_execute` 请求头被拒绝，且客户端仍退出 0；已修复其单命令路径并保留最初错误正文。批处理、别名和完整交互继续作为缺口，命令正文与副作用检查不能被退出码代替。

详见 [ESL 接口说明](esl-reference.md) 和 [协议说明](protocol-reference.md)。

### SIP TCP/TLS 与媒体生命周期

保留默认 UDP 行为，通过可选 `sip.stream` 开启 TCP/TLS 监听及固定上游传输。真实连接身份贯穿呼叫、事务、缓存和响应来源；可靠传输沿原连接回包，断线不会降级到 UDP 或复用相同地址的新连接。

单条 SIP 消息上限 16 KiB，每连接发送队列最多 16 条，默认最多 256 条连接，包含握手中的连接。整帧期限从首字节开始计算，分片到达不会不断延长期限；TLS 校验证书链和名称，没有跳过校验开关。异常关闭直接关闭底层 socket，避免 TLS 关闭通知阻塞呼叫主循环。

可靠传输不重传请求；非 2xx 最终响应与 INVITE 2xx 的端到端 ACK 规则分别处理。连接断开只清理所属通话、事务和缓存，避免短连接反复扫描全部通话。新增回归覆盖 5000 个无关通话下的归属清理，以及长期连接一万次周转后的索引回收。

SIPS 路由、DNS NAPTR/SRV、IPv6、SCTP、WS/WSS、WebRTC、ICE、DTLS-SRTP、REGISTER/鉴权、re-INVITE、UPDATE、PRACK、REFER、会话定时器及双向 TLS 客户端认证尚未完成。TLS 信令成功不代表媒体加密或这些扩展已经支持。

### 原版成对结果及剩余差异

最终成对报告于 `2026-09-06T09:33:41.060021Z` 完成。21 项通过主要覆盖认证、UTF-8 回显、粘包/分片、CRLF、后台作业、缺失 UUID 查询/语法、命令大小写、事件筛选及原版 fs_cli 所用单 API 控制台包装的限定断言。实际原始双端报文保留在 [完整成对报告](conformance-report.md)；执行方法见 [成对测试用例与判定标准](conformance-testing.md)。

三个失败探针分别为 UDP、TCP、TLS 的 OPTIONS 能力比较。两端均返回 200，但 FreeSWITCH 还宣告 INFO、MESSAGE、NOTIFY、REFER、REGISTER、UPDATE 等方法，以及 path、replaces、timer 等扩展；RustSwitch 当前只有基础 INVITE、ACK、CANCEL、BYE、OPTIONS 子集。因此保留真实差异，不通过复制原版能力头来伪造这些功能已经实现。

API 目录逐项发现覆盖 292 条源码注册记录：原版当前配置实际暴露 189 行，RustSwitch 暴露 9 行。103 条因原版对应模块未加载而不能在本基线上完成运行检查，180 条在候选产品没有入口，9 条仍需更多语义分支验证。入口名称相同不代表输入、错误、事件及副作用完全相同。

### 5000 路容量回归

环境为共享宿主上的 8 vCPU／2 GiB Linux 虚拟机；PCMU 20 ms、5000 路、100 CPS、双向媒体 10 秒，标称 5,000,000 包。总量和每路每方向均要求至少达到标称 98%，并检查实际丢失、重复、错误、拆线与资源清理。验收阈值保持不变。

| 运行 | 程序 | 实际发送 | 唯一接收 | 标称提供率 | 结果 |
|---|---|---:|---:|---:|---|
| capacity-01 | 新 1.5 | 1,843,805 | 1,843,805 | 36.8761% | 未通过 |
| capacity-02 | 新 1.5 | 2,824,745 | 2,824,745 | 56.4949% | 未通过 |
| capacity-03 | 新 1.5 | 4,493,465 | 4,493,465 | 89.8693% | 未通过 |
| capacity-04 | 新 1.5 | 2,407,092 | 2,407,092 | 48.14184% | 未通过；发送写错误 8 次 |
| capacity-old-01 | 旧 1.4 对照 | 4,312,335 | 4,312,335 | 86.2467% | 未通过 |

此前四轮都实际接通 5000 路，已发送与唯一接收相等，拆线和资源清理完成，但未提供足够负载。最新 capacity-04 也接通 5000 路，已发送与唯一接收各为 2,407,092 包，标称提供率 48.14184%，发生器发送写错误 8 次；接收端未发现已经发送包的缺失，不能据此将本轮表述为“零错误”。该轮拆线及资源清理完成，仍因负载不足及发送写错误未通过。本轮不能声明 5000 路容量通过。以前 1.4 的两次成功记录继续作为历史证据保留，不自动继承给当前构建。

新旧使用相同 Rust 媒体程序，发生器主代码和负载参数一致。媒体稳定段没有控制队列积压或随通话数增长的协程/线程。本次停止专用原版进程、观察宿主活动状态后负载提供率变化，旧版在相同当前环境也不足；这些结果不能单独证明代码或宿主调度是唯一原因。各轮并非同时运行，不能把环境随时间变化全部归因于优化。还需稳定资源窗口或后续独立 Linux 服务器复验。

## 交付及离线复核

1.5 使用新的源码包、文档包、证据包和外部 SHA-256 清单，不覆盖 1.3、1.4 交付物。

证据包保留最新与历史运行收据、绑定二进制、原版构建/来源/安装指纹、成对报告、容量失败记录、状态采样、事件日志和资源清理原件。正式运行结论只属于收据绑定的程序；最终宿主控制程序可能因嵌入文档而重建，不能用其新哈希替换原实测程序身份。

不公开运行密钥、证书私钥、配置口令、凭据环境、CSRF、用户管理状态或未脱敏的原版安装归档。原版采集日志中的认证发送帧仅提供明确标注的脱敏副本，同时记录原文件摘要和处理说明；其他报文不改写。源码中公开配置示例与官方默认模板按原样保留，不能拿示例口令作为生产凭据。

每个归档都有逐文件 SHA-256 索引。离线复核先检查归档路径、重复成员、文件长度和摘要，再从源码包的独立临时目录运行文档发布检查，确认文档、对照、源码和证据一致；该检查不启动服务器、不访问现网、不重新执行容量测试。
