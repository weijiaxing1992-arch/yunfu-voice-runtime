02 RustSwitch 部署拓扑

本章描述主工程的进程部署、网络连线与资源隔离。图中的外部系统需要部署方另行提供；候选或规划连线不代表已经完成业务集成。模块内部职责见 软件架构。

基线部署拓扑

主服务由一个 Go 控制进程和多个 Rust 媒体子进程组成。SIP 信令进入 Go，RTP/RTCP 进入承担该通话的 Rust 进程。控制进程启动和监督自己的媒体子进程，同时提供回环 HTTP 管理接口；无需单独部署 Node.js 前端服务。

外部线路、可信 SBC 和 SIP 终端属于独立系统。当前主要接入模型是可信 IPv4 对端和单个固定上游，不能据此推定已提供完整终端注册服务器、多运营商网关或公网 NAT 穿越。管理端通过服务器本机浏览器或 SSH 隧道接入。

连线 方向与用途 默认/示例
SIP 可信 A 侧 ↔ Go ↔ 固定上游 B 侧 sip.listen 本地 UDP 5060；sip.upstream 上游 5070；TCP/TLS 需显式配置
媒体 A/B ↔ 分配该通话的 Rust worker 本地示例 UDP 20000–21999，每通话预留四端口
HTTP 管理员/脚本 → Go 127.0.0.1:9080；26 个操作及静态页面
ESL 本机业务控制 → Go 默认关闭；显式示例 127.0.0.1:8021
JSONL IPC Go ↔ 每个 Rust 子进程 stdin/stdout；诊断走 stderr
PCM/RX Go ↔ Rust 分别经继承的 FD3/FD4 传递媒体数据，不是网络监听端口
RVA1 本机业务代理 → Go → Rust 显式私有 Unix socket；流式 PCM 下行
文件 Go → 本地持久化目录 journal.path 事件文件，及其路径追加 .admin.json 后的管理状态文件

本地地址和端口来自 source/main/config/local.json。监听地址、对外通告地址和远端地址职责不同：修改本机监听不会自动修改对端 SDP；SIP 与媒体白名单也需分别维护。当前管理监听必须为 IPv4 回环地址，不能直接将 admin.listen 改为公网或通配地址。

语音智能体接入拓扑

蓝色部分表示主工程已有媒体路径；橙色 ASR1 表示已有实现和限定历史验证的独立候选；灰色模型和业务编排属于外部或待集成范围。候选源码已随公开交付包提供，但未合入主工程。当前没有通用 gRPC/WebSocket Agent 服务，图中的外部模块不对应额外的已实现 API。

本地 RX 与下行 TX 相互独立。上行只观察对端 A 腿，不把本地 TTS 播放回灌成用户音频。内部保留原生采样率，ASR 分支需要 16 kHz 时才转换；不能将所有媒体写成统一 16 kHz 在线处理已完成。

RVA1 是本机私有 Unix socket 下行入口，RXS2 是收音合同，ASR1 是候选代理合同，三者格式和身份约束不同。Unix socket 所在目录、服务用户及文件权限必须与运行配置匹配；把进程移动到另一台机器不能直接沿用这些本机通道。

压测拓扑与资源隔离

后台测试页启动独立的被测控制实例、媒体进程和发生器，并在运行总览中单独展示测试观测。判断数据时仍需核对任务 ID、进程身份和样本时间，不能把测试连接数计入主业务通话数。

同机测试共享 CPU、内核、内存和网卡，端口分离不等于硬件隔离。目标容量验收应使用明确分配资源的 Linux 被测机，并考虑独立发生器；本地开发测试或已有有限 VM 探针不等同于这种环境的完整容量结果。

测试子实例不会使用主服务线路凭据注册真实运营商。容量模式仅关闭它自己的业务软保护，硬并发/CPS、媒体健康和资源边界仍生效。不能占用主媒体范围来消除压测预检失败。

端口与容量规划

当前分配器以 A/B 两腿各自的 RTP/RTCP 四端口块规划资源，尾部不足四端口的部分不可用。存在 excluded_port_blocks 时还需扣除显式排除块：

可用块数 = floor((port_end - port_start + 1) / 4) - 排除块数
最低全局预算 = max_calls + ceil(calls_per_second × port_reuse_delay_ms / 1000)

端口范围必须从不小于 1024 的偶数开始，结束端口不大于 65535；排除项必须是范围内按起点对齐的完整四端口块。全局预算通过后，还需考虑各媒体进程的端口分区、短时周转、文件描述符以及实际收发能力。

示例 可用块数与启动预算 用途
本地 20000–21999，100 路、20 CPS、2 秒隔离 500 块；最低预算 140 块 回环开发和受限功能验证
Linux 10000–64999，10000 路、1000 CPS、2 秒隔离 13750 块；最低预算 12000 块 待按目标环境验证的配置模板

上述是静态资源预算，不是吞吐结果。示例未启用排除块；使用排除块或变更周转速率后须重新计算。

部署形态与交接资料

形态 适用阶段 需要明确的边界
单机回环 安装试用、单路模拟、接口开发 默认上游没有真实线路；主工程与候选端口相同
单台 Linux + 可信 SBC 线路互通与受控试运行 实际通告 IP、两类白名单、密钥文件、端口和服务用户
Linux 被测机 + 独立发生器 业务等价性能和长时间测试 硬件、网络、编码、时长、发生器能力、原版基准与逐流结果

部署交接至少应记录版本/哈希、地址与端口表、服务用户、配置与状态文件位置、排空/回滚流程，以及已通过和未覆盖的验证范围。主控制进程或整机故障时，当前没有活动通话跨机无损接管。

Linux 配置入口为 source/main/config/linux-10000.example.json。其中 198.51.100.* 是文档示例地址，必须按真实 IP、CPU、线路和压测机调整；不要将示例直接安装为生产配置。具体启动和运维步骤见 使用说明 与 运维和压力测试。
