11 交付与源码说明

RustSwitch 的公开交付包含主工程、独立 ASR 候选、测试与工作补丁、固定依赖、完整项目资料和两个 ARM64 平台的预编译程序。本章说明如何选择源码、构建产物和验证依据。

首个发行版本 v0.1.0-preview.20260908 已公开，绑定提交 54fcd571874d599b10611dc7f38f2a751a433c94。该发行的 4,991 个 Git 文件及 8 个附件已完成上传核对。后续 main 分支的文档更新单独通过 Git 记录，不替换已发布附件或重写历史证据。

离线构建

需要 Python 3.9+、Go 1.23+、Rust/Cargo 1.85+ 和支持 C11 的本机 C 编译器。macOS 还需要开发工具与系统 SDK；工具链本身不随源码包分发。最低版本来自源码声明和脚本用法，已记录的构建使用 Go 1.27.1、Rust 1.98.1，并未逐个最低版本重建。

从仓库或完整源码包根目录执行：

python3 delivery-tools/build_source.py \
  --variant main \
  --output ../rustswitch-build-main

python3 delivery-tools/build_source.py \
  --variant asr-candidate \
  --output ../rustswitch-build-asr

输出目录必须尚不存在且位于资料目录之外。脚本核对源码清单，使用 Go -mod=vendor、Cargo --locked --offline 与随包依赖，生成控制程序、callbench、Rust 媒体和 G.711 C ABI 示例；候选另生成 asr-mock。可通过 GO、CARGO、CC 指定工具位置。结果与各步骤日志保存在输出目录，查看 receipt.json 的 passed 和 source_unchanged。

基础构建复用现有内嵌文档，不重新生成后台资料，不运行 SIP、容量或完整功能验收。G.722/Opus 为额外原生后端，按原生音频说明单独构建。完整启动、路径组装和配置检查步骤见 快速开始。

原始工程的 make all 会进入文档构建步骤；当前两份源码的文档门禁仍有记录在案的失败，详见 当前能力与验证状态。开发构建通过不应被描述为完整发布验收通过。

预编译程序与验证材料

平台 包含内容 使用范围
macOS ARM64 主工程、ASR 候选及可选原生动态库 完整包按 macOS 26+／Apple Silicon 使用；开发构建未做 Developer ID 公证
Linux ARM64 主工程及 ASR 候选静态核心程序 aarch64；不含可选 G.722/Opus .so；候选组合尚未在 Linux 完成整组联调

当前没有 Linux x86_64 预编译包。预编译附件保留 20 个原构建文件的字节与身份；公开副本的文本整理不会同步改写可执行文件里的历史文档。Linux 主工程保留的限定探针记录不构成容量验收。

发行附件 public-build-checks.json 记录公开副本的离线构建和配置检查；publication-validation.json 记录分发内容与链接校验。原始开发构建收据保留于 main 和 ASR 候选。这些文件分别描述自己的执行范围，不能互相替代。

完整性、许可与后续修改

下载时使用同一发行中的 SHA256SUMS.txt 核对附件，再按运行包 verify.py 核对解压内容。source/*-manifest.json、整包 manifest.json 和运行包清单分别对应自己的材料范围；源码发生修改后，旧快照清单不再是新源码的身份声明。

自有原创代码和资料采用 Apache-2.0。G.722 支持文件、SpanDSP、FreeSWITCH 模板及其他依赖保留各自许可，详见 开源说明、许可范围和第三方清单。实际运行密钥、服务状态、socket 和开发缓存不在源码交付范围内。

后续贡献应通过新的提交记录变更，以新证据更新适用功能状态；发行附件和历史收据保持冻结。完整任务边界见 需求说明书与未完成清单。
