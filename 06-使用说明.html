06 RustSwitch 使用说明

本章供安装、线路接入和业务控制人员使用，说明配置生效、后台操作、可信 SIP 线路、IVR、音频接口及停止流程。首次安装先完成 快速开始，容量与故障处理见 运维和压力测试。

除另行说明外，./bin/rustswitch 等命令从包含 bin/、config/ 的运行目录执行；维护源码时，主工程根为仓库内的 source/main/。主工程与 ASR 候选是独立版本，不能混用程序或同时占用相同示例端口。启动、配置保存和测试操作均会产生实际状态变化。

1. 确认工程和版本

公开仓库主工程位于 source/main/，ASR 候选位于 source/asr-candidate/。部署时记录所用 Release/提交、二进制哈希、平台和配置位置。已有服务可只读查询：

curl --fail --silent --show-error http://127.0.0.1:9080/healthz
curl --fail --silent --show-error http://127.0.0.1:9080/v1/docs
curl --fail --silent --show-error http://127.0.0.1:9080/v1/status

/healthz 检查进程响应，/readyz 检查瞬时新准入状态，/v1/docs 中的 version 是内嵌文档版本。组件版本和文档版本不是同一编号。连接失败时应先检查进程与监听，不能推断服务已经安装或升级；仅文档更新也不会替换正在运行的二进制。

2. 准备环境和构建

使用预编译运行包或固定快照离线构建时，按 快速开始 操作。开发维护使用工程 Makefile，声明要求 Go≥1.23、Rust≥1.85、C11 编译器和 Python；完整静态检查还需要 rustfmt/clippy。离线交付脚本要求 Python≥3.9。保持 Cargo.lock 和 Go vendor，不删除锁文件以绕过依赖问题。

# 从公开仓库根目录进入主工程；此流程会构建产物并执行文档生成门禁。
cd source/main
make all
./bin/rustswitch -check-config -config config/local.json

make all 包括文档生成门禁、Go 控制程序、Rust 媒体、callbench 和 C 插件示例；它不是离线交付构建脚本，也不自动运行完整测试。当前主工程门禁有 PCM 证据过期问题，候选有字段字典不同步问题，需按 未完成清单 修复和重新验收。macOS 二进制不能直接在 Linux 使用，架构也必须匹配。

3. 本地启动与最小试用

./bin/rustswitch -config config/local.json

默认示例：后台 9080、SIP 5060、固定上游 5070，100 路硬并发、20 CPS、2 个媒体 worker，RTP/RTCP 范围 20000–21999。相对媒体程序和日志路径按进程工作目录解析，应从当前安装的运行目录启动；media.playback_root 则要求明确的绝对路径。首次启动前运行 ./bin/rustswitch -config config/local.json -check-config，校验通过不等于真实端口或线路可用。

打开 http://127.0.0.1:9080/#tests 选择“小电话”，执行单路 SIP/媒体测试。它使用隔离模拟端点核验建立、双向媒体和挂断，不是浏览器麦克风/WebRTC 电话，也不是对任意外部分机拨号。

4. 后台操作顺序

后台由控制程序内嵌提供，访问根地址即可。先查看运行总览和实际配置，再修改保护策略或线路参数，最后执行单路验证。

页面 操作与结果
运行总览 看主业务活跃/接通、分片、日志、保护；测试数据在独立区域，旧数据需看时间
峰值保护 调整即时 Guard；配置持久化成功后生效，不重启，不挂断存量呼叫
SIP 与媒体/运维配置 编辑完整 desired；保存不切换 active，重启后才按持久化规则应用
FreeSWITCH 配置 编辑/导出 XML 工作区；不自动成为运行拨号计划
兼容能力/FreeSWITCH 对照 按状态和原始 ID 查范围、差异、验证；绿色只表示所列有限断言
压力与电话测试 选择 500/1000/2000/3000/5000/自定义、观察进度、停止、下载报告
接口文档 查看固定版本的机器模型、专题与对照，下载完整 ZIP

配置有三种不同的状态与生效方式：

状态或操作 如何判断
active 本进程实际启动配置；监听、媒体分片和硬限制以它为准
desired 已保存的待启动配置，restart_required 指示是否与 active 不同
Guard 在线策略 保存成功后作用于后续新呼叫；降低阈值不会主动挂断存量呼叫
XML 工作区 保存/导出配置资料；运行 XML 拨号计划是另一个显式启动入口

管理状态存于 journal.path 后追加 .admin.json 的文件，不直接改写启动 JSON。再次启动和 -check-config 会按持久化规则读取待启动配置，所以恢复环境时要同时处理启动配置与管理状态。

多个页面共享 revision。遇到 HTTP 409，保留草稿、重新读取并人工合并，不能仅替换 revision 盲重试。写入需要当前进程的 CSRF token；CSRF 不是远程账户认证。本版本要求管理监听为回环地址，并校验请求 Host/Origin；远程运维可使用如下 SSH 隧道，将示例别名换成自己的主机：

ssh -N -L 9080:127.0.0.1:9080 your-server-alias

随后在本机访问 http://127.0.0.1:9080。本机 9080 已被占用时应选择其他本地端口；这不会改变服务器的监听配置。

5. 接入可信线路

先配置真实 SIP/媒体地址和白名单，再验证单固定上游呼叫。按以下顺序核对：

  1. 设置 sip.listen、sip.advertise 和 sip.upstream；目的地使用实际 IPv4 地址与端口。
  2. 设置 media.bind_ip、media.advertise_ip 和可用 RTP/RTCP 范围。
  3. 分别配置 sip.trusted_networks 和 media.allowed_remote_networks，保留最小必要范围。
  4. 需要注册时添加 sip.registration，需要 Digest 认证时配置 sip.trunk_auth 与私有密码文件。
  5. 配置校验后按排空/重启流程应用，检查注册状态，再验证呼叫、双向媒体和挂断回收。

以下仅是 sip 内部补充，不可当作完整配置 PUT，也不包含实际运营商账户：

{
  "trunk_auth": {
    "username": "line",
    "password_file": "/etc/rustswitch/trunk.password",
    "realm": "carrier.example"
  },
  "registration": {
    "aor": "sip:line@carrier.example",
    "registrar_uri": "sip:carrier.example",
    "expires_seconds": 300,
    "retry_seconds": 30,
    "timeout_ms": 8000
  }
}

密码文件为同用户可读的私有普通文件，示例权限 0600/0400；不要写到 URL、命令行或提交的源码中。实际网络目的地是 sip.upstream 的 IPv4 地址和端口；URI 域名不等于已实现 DNS/SRV 路由。TCP/TLS 需配置各自监听，TLS 校验证书链和名称。注册成功后再核验真实呼入/呼出与双向媒体，不能只看 registered。

完整 JSON、TLS 字段与限制见 线路注册合同。当前没有可直接代替 FreeSWITCH originate 的公开调用；主动外呼须由受控 SIP 发起方进入现有线路桥接路径，通用业务外呼 API 仍待实现。

6. 本地接听、IVR 和按键

在 sip 添加 local_extensions: ["1000", "1001"]；需要本地 G.711 PCM/ASR 路径时同时按合同设置 media.processing: "g711"。这是配置片段说明，保留完整基础配置并先执行 check-config。

本地号码精确匹配，媒体分配成功才应答，正确 ACK 后才能读写媒体。受限 XML 拨号计划是另一个启动冻结入口；启用后未匹配返回 404，不自动回退固定上游。

启用 ESL 示例：

./bin/rustswitch -config config/local.json \
  -esl-listen 127.0.0.1:8021 \
  -esl-password-file /absolute/private/esl.secret

ESL 默认关闭；-esl-listen 与 -esl-password-file 必须同时提供。示例密钥文件路径需替换为真实私有文件，内容为一行非空密码，不能将账户密码直接放在命令行。

从 CHANNEL_CREATE 取得真实 UUID，订阅 CHANNEL_ANSWER、CHANNEL_EXECUTE_COMPLETE、DTMF、CHANNEL_HANGUP 等，匹配应用关联 ID。使用 协议与 SDK 的 read 示例后查看 menu_choice、read_result 和 read_terminator_used，区分成功、超时、输入不完整和挂断。+OK 表示命令受理，不等于播放或收号已经完成。播放格式、提示文件和停止语义见 IVR 合同。

7. HTTP 客户端正确写入

下面演示先读取现状，再将同一份完整 Guard 策略写回的 token/revision 流程。执行后会发生一次真实保存并推进版本，不是只读检查。修改实际阈值前阅读 容量保护说明。

import json, urllib.request, urllib.error
base = "http://127.0.0.1:9080"
def get(path):
    with urllib.request.urlopen(base + path, timeout=5) as r:
        return json.load(r)
config = get("/v1/config")
guard = get("/v1/guard")
# 使用同一GET快照的revision及完整policy；若期间有其他写入，409需重新合并。
body = {"revision": guard["revision"], "policy": guard["guard"]["policy"]}
request = urllib.request.Request(base + "/v1/guard", method="PUT",
    data=json.dumps(body).encode(),
    headers={"Content-Type":"application/json",
             "X-RustSwitch-CSRF":config["csrf_token"]})
try:
    with urllib.request.urlopen(request, timeout=5) as r:
        print(json.load(r))
except urllib.error.HTTPError as error:
    # 不盲目覆盖其他操作者的配置，也不输出凭据。
    if error.code == 409:
        raise SystemExit("配置版本已变化，请重新读取并合并后再保存") from None
    raise

写入网络超时可能发生在已经提交之后，应先 GET 核对实际状态。对要求 request_id 的测试任务创建接口，重试还应复用原标识；不能把该字段套用到不接受它的 Guard 请求。完整模型与错误码见 HTTP 接口 和 数据模型。

8. PCM 与 ASR 接入

外部 TTS 适配器目前需要自行准备 8 kHz mono S16LE，在已 ACK 的本地通道上走 RVA1 BEGIN/DATA/END；不要把 HTTP JSON 当成每 20 ms 送音通道。实际 TTS 厂商连接未由此自动完成。

ASR 候选提供 asr_stream 部署配置和内部 Server.StartASR。它先与本机私有 ASR1 代理握手，再申请真实 RX；保留 8 kHz 原生收音或按需转换到 16 kHz。业务需持续读取 Next，调用 Finish 后仍取结果，并等待有效 DONE 与实际清理。候选 asr-mock 仅核验 PCM 摘要；真实模型与完整 Agent 仍需接入。部署字段和方法见 候选合同。主工程没有 StartASR HTTP URL。

9. Linux 安装与停止

可从 source/main/deploy/rustswitch.service 取得 systemd 模板。安装前完成如下准备：

对象 模板约定与部署要求
服务身份 创建专用 rustswitch 用户和组，使其能读取程序、配置及需要的私有文件
程序与工作目录 /opt/rustswitch/bin/；工作目录 /opt/rustswitch
启动配置 /opt/rustswitch/config/production.json，由部署方基于实际地址生成并校验
可写状态目录 /var/lib/rustswitch，配置的事件、管理状态和需要持久化的数据应与权限策略一致
文件描述符 LimitNOFILE=262144 是模板预算，仍需核对系统和运行进程实际限额
停止与重启 Restart=on-failure、KillMode=mixed、TimeoutStopSec=3640；重启不恢复已中断的活动通话

模板启用 ProtectSystem=strict、ProtectHome=true 等限制。提示文件、密钥和本机 socket 路径必须在该服务上下文可访问；不要让配置继续引用开发者的 home 目录。安装 unit 后先验证配置和单路服务行为，再按变更流程开放线路流量。

停止前可通过后台/API 进入排空状态，阻止新准入并观察存量通话结束。首次 SIGTERM/SIGINT 进入正常退出流程，等待存量通话和注册注销；第二个信号强制取消。HTTP 排空与进程退出不同：普通排空可以恢复接入，已经开始停止的进程不能用恢复接口撤销退出。systemd 的 3640 秒等待与示例最长通话相关，需按实际通话和 SIP 清理期限核验。

回滚应保留旧二进制、启动 JSON、管理状态、许可和验证记录；先排空并确认新进程退出，再切换到已验证组合。回滚后复查 active/desired、保护策略、注册和单路媒体，当前不提供跨版本活动通话迁移。
