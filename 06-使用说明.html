06 使用说明

本章命令是供操作者在自己的实验环境执行的示例；资料生成过程没有启动、停止或修改电话服务。主工程与 ASR 候选不是同一安装版本，先按第 1 步确认自己所在目录。

1. 确认工程和版本

公开仓库主工程位于 source/main，ASR 候选位于 source/asr-candidate。首次使用请按 快速开始 的离线构建或预编译运行包流程操作；以下 make all 是完整工程门禁路径，当前仍有文档门禁阻塞。已有服务可只读查询：

curl --fail --silent --show-error http://127.0.0.1:9080/healthz
curl --fail --silent --show-error http://127.0.0.1:9080/v1/docs
curl --fail --silent --show-error http://127.0.0.1:9080/v1/status

healthz 仅说明进程可响应，readyz 只说明瞬时新准入状态，docs.version 才是其内嵌文档版本。连接失败不返回版本。本资料生成时后台未连接成功，不表示曾经部署的版本被自动更换。

2. 准备环境和构建

需要 Go≥1.23、支持项目的 Rust stable（最低 1.85）、C 编译器、Python 3；校验需 rustfmt/clippy。按仓库锁定的 Cargo.lock 和 Go vendor 构建；不要删除锁文件以绕过编译错误。

# 在主工程根目录执行
make all
bin/rustswitch -check-config -config config/local.json

make all 包括文档门禁、Go 控制程序、Rust 媒体、callbench 和 C 插件示例。若文档证据与改动后的源码不一致，门禁会明确失败，需按发布流程重新验收，不应跳过门禁宣称新版本已验证。Mac 二进制不能直接拿到 Linux 运行，须在目标平台构建。

3. 本地启动与最小试用

bin/rustswitch -config config/local.json

默认示例：后台 9080、SIP 5060、固定上游 5070，100 路硬并发、20 CPS、2 个媒体 worker，RTP/RTCP 范围 20000–21999。相对媒体程序、提示文件、日志路径按进程工作目录解析，保持从项目根目录启动。

打开 http://127.0.0.1:9080/#tests 选择“小电话”，执行单路 SIP/媒体测试。它使用隔离模拟端点核验建立、双向媒体和挂断，不是浏览器麦克风/WebRTC 电话，也不是对任意外部分机拨号。

4. 后台操作顺序

页面 操作与结果

多个页面共享 revision。遇到 409，保留草稿、重新读取并人工合并，不能仅替换 revision 盲重试。写入需要最新 CSRF；CSRF 不是远程账户认证。远程运维可用 ssh -L 9080:127.0.0.1:9080 <自己的SSH主机别名> 后访问本机地址；本例不包含任何真实主机凭据。

5. 接入可信线路

先配置真实 SIP/媒体地址和白名单，再建立单固定上游呼叫。需要 REGISTER 时，增加 sip.registration；需要认证时配置 sip.trunk_auth。以下仅是 sip 内部补充，不可当作完整配置 PUT：

{
  "trunk_auth": {
    "username": "line",
    "password_file": "/etc/rustswitch/trunk.password",
    "realm": "carrier.example"
  },
  "registration": {
    "aor": "sip:line@carrier.example",
    "registrar_uri": "sip:carrier.example",
    "expires_seconds": 300,
    "retry_seconds": 30,
    "timeout_ms": 8000
  }
}

密码文件为同用户可读的私有普通文件，示例权限 0600/0400；不要写到 URL、命令行或提交的源码中。实际网络目的地是 sip.upstream 的 IPv4 地址和端口；URI 域名不等于已实现 DNS/SRV 路由。TCP/TLS 需配置各自监听，TLS 校验证书链和名称。注册成功后再核验真实呼入/呼出与双向媒体，不能只看 registered。

完整可用 JSON 与 TLS 字段见 线路注册。当前没有可直接代替 FreeSWITCH originate 的公开调用；主动外呼须由受控 SIP 发起方进入现有线路桥接路径，完整业务外呼 API 仍待实现。

6. 本地接听、IVR 和按键

在 sip 添加 local_extensions: ["1000", "1001"]；需要本地 G.711 PCM/ASR 路径时同时按合同设置 media.processing: "g711"。这是配置片段说明，保留完整基础配置并先执行 check-config。

本地号码精确匹配，媒体分配成功才应答，正确 ACK 后才能读写媒体。受限 XML 拨号计划是另一个启动冻结入口；启用后未匹配返回 404，不自动回退固定上游。

启用 ESL 示例：

bin/rustswitch -config config/local.json \
  -esl-listen 127.0.0.1:8021 \
  -esl-password-file /absolute/private/esl.secret

从 CHANNEL_CREATE 取得真实 UUID，订阅 CHANNEL_ANSWER、CHANNEL_EXECUTE_COMPLETE、DTMF、CHANNEL_HANGUP 等，匹配应用关联 ID。使用 05 的 read 示例后查看 menu_choice、read_result 和 read_terminator_used，区分成功、超时、输入不完整和挂断。playback 支持范围、提示文件格式及停止语义见 IVR。

7. HTTP 客户端正确写入

下面只读取得完整现状并写回同一保护策略，演示 token/revision 处理；运行后仍会进行一次真实保存并推进版本。修改策略前阅读 07。

import json, urllib.request
base = "http://127.0.0.1:9080"
def get(path):
    with urllib.request.urlopen(base + path, timeout=5) as r:
        return json.load(r)
config = get("/v1/config")
guard = get("/v1/guard")
# 使用同一GET快照的revision及完整policy；若期间有其他写入，409需重新合并。
body = {"revision": guard["revision"], "policy": guard["guard"]["policy"]}
request = urllib.request.Request(base + "/v1/guard", method="PUT",
    data=json.dumps(body).encode(),
    headers={"Content-Type":"application/json",
             "X-RustSwitch-CSRF":config["csrf_token"]})
with urllib.request.urlopen(request, timeout=5) as r:
    print(json.load(r))

写入网络超时可能发生在已经提交之后。先 GET 核对，不要为每次重试生成新的 request_id 或盲目重放操作。完整字段以 04 和 09 为准。

8. PCM 与 ASR 接入

外部 TTS 适配器目前需要自行准备 8 kHz mono S16LE，在已 ACK 的本地通道上走 RVA1 BEGIN/DATA/END；不要把 HTTP JSON 当成每 20 ms 送音通道。实际 TTS 厂商连接未由此自动完成。

ASR 候选新增部署 asr_stream 和内部 Server.StartASR。它先与本机私有 ASR1 代理握手，再申请真实 RX；8 kHz 原生或按需 16 kHz。业务持续 Next，Finish 之后仍取结果，等待有效 DONE 与实际清理。候选 asr-mock 仅核验 PCM 摘要；真实模型与完整 Agent 还需接入。部署字段和所有方法见 候选合同。主服务基线没有新增 StartASR HTTP URL。

9. Linux 安装与停止

可审阅 systemd 模板：默认工作目录 /opt/rustswitch、专用用户、LimitNOFILE=262144、仅 /var/lib/rustswitch 可写。需自行创建用户/目录，并使 production.json 的日志、状态和文件权限与这些路径一致。模板存在不等于本机已安装服务。

停止前先排空新接入并观察真实通话归零。首次 SIGTERM 进入正常退出流程，等待存量通话和注册注销；重复终止信号会强制结束。systemd 默认 3640 秒等待与示例最长通话相关，生产需按实际超时策略核验。

回滚保留旧二进制、配置、许可与证据；先排空并确认本次进程退出，再按部署流程切换。当前不提供跨版本活动通话迁移。
