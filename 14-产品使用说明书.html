RustSwitch 产品使用说明书

开发预览 · 2026-09-23

RustSwitch（历史资料中亦称“云蝠 Voice Runtime”）是面向电话语音智能体的实时语音内核，采用 Rust 媒体层、Go 控制面和 C/C++ 编解码适配。本文将安装、配置、单路通话、后台操作、压测和排障串成一条可执行的试用流程；细节由文末接口合同和专题文档补充。

产品状态：开发预览。 当前提供受限 SIP 呼叫与固定上游注册、RTP/RTCP、G.711 实时处理、本地播放与按键收集、入站 ESL 子集、PCM/RX 音频接口和管理后台。完整 FreeSWITCH/PBX 替换、终端注册服务、通用 originate、会议、队列、WebRTC、真实 ASR–LLM–TTS 链路与 5,000/10,000 路容量尚未完成整体验收。管理页面显示的能力或配置上限不能代替真实业务验收。

1. 获取产品

公开仓库：yunfu-voice-runtime。主工程源码位于 source/main，独立 ASR 候选位于 source/asr-candidate；候选带 mock 供应商，不提供真实语音识别。首次试用请选择主工程。

固定预览版：v0.1.0-preview.20260908。目前提供 macOS ARM64 和 Linux ARM64 运行包，没有预编译 x86_64 包。压缩包内有平台说明、文件清单和许可材料；选定平台后先运行包内的 verify.py，再继续安装。不要混合不同包内的控制程序、媒体程序和配置。

获取当前源码并校验仓库材料：

git clone https://github.com/weijiaxing1992-arch/yunfu-voice-runtime.git
cd yunfu-voice-runtime
python3 delivery-tools/verify_delivery.py

文件完整性校验只检查路径、大小和 SHA-256；它不证明功能或容量通过。若修改了源码，历史清单不再匹配属于预期现象。复现固定发行版时，克隆命令增加 --branch v0.1.0-preview.20260908。

2. 安装前检查

项目 本地试用要求
操作系统与架构 选择匹配的 ARM64 运行包；源码构建按目标系统分别执行。
工具链 源码构建需要 Python 3.9+、Go 1.23+、Rust/Cargo 1.85+ 和 C11 编译器。最低版本来自源码声明，部署时应在目标平台验证。
目录 准备单独运行目录；保证服务用户能读取配置、执行程序并写入日志与状态目录。
端口 示例后台 9080、SIP 5060、上游 5070、媒体 20000–21999。先确认没有被其他服务占用。
网络 默认绑定回环地址；接入真实线路前，设置可达的宣告地址、最小可信网段与防火墙规则。
凭据 线路和 ESL 密码使用私有文件，按服务用户授予最小读权限；不要加入 Git 或公开日志。
压测 使用隔离 IP、媒体端口或独立发生器，先完成资源预检；测试端口不得侵占主服务媒体范围。

本地示例默认硬并发 100、20 CPS、2 个媒体 worker。它们是开发配置，不是生产容量建议。

3. 构建与启动

如果已下载预编译运行包，从解压后的包根目录执行：

python3 verify.py
cd main
./run.sh -check-config
./run.sh

若 run.sh 在当前平台尚无执行权限，先按 快速开始 的说明授权。不要在已有运行目录上覆盖正在使用的程序。

从源码构建时，在仓库根目录执行，输出目录必须位于仓库外且尚不存在：

python3 delivery-tools/build_source.py \
  --variant main --output ../rustswitch-build-main

构建成功后得到 Go 控制程序 rustswitch、发生器 callbench 和 Rust 媒体程序 rustswitch-media。按照 快速开始 将它们与 source/main/config/local.json 放入单独运行目录，然后在该目录执行：

./bin/rustswitch -config config/local.json -check-config
./bin/rustswitch -config config/local.json

构建脚本使用固定依赖、不启动服务。配置检查通过不表示监听端口空闲或真实 SIP 线路已经可用。源码修改后若交付构建拒绝快照校验，应走 主工程开发入口，保留变更与测试记录。

4. 首次健康检查与后台

服务启动后，打开 http://127.0.0.1:9080。先做只读检查：

curl --fail --silent --show-error http://127.0.0.1:9080/healthz
curl --fail --silent --show-error http://127.0.0.1:9080/readyz
curl --fail --silent --show-error http://127.0.0.1:9080/v1/status
curl --fail --silent --show-error http://127.0.0.1:9080/v1/docs

healthz 检查进程响应，readyz 表示当前新呼叫准入状态。status 和 docs 分别提供运行状态及内嵌接口版本。这些结果不代表呼叫或媒体验收。

页面 主要操作 生效与判断
运行总览 查看呼叫、分片、日志、保护和压测任务状态 区分主业务与测试数据，检查采样时间。
峰值保护 调整并发、建立中呼叫和 CPS 限额 Guard 保存后影响新的呼叫；降低阈值不会主动挂断已接通的通话。
SIP 与媒体/运维配置 修改监听、媒体、日志与其他 desired 配置 保存后查看 restart_required；需重启的字段不会即时成为 active。
FreeSWITCH 配置 编辑或导出 XML 工作区 导出的文件不会自动成为运行拨号计划，也不会装载同名模块。
压力与电话测试 单路小电话、隔离并发测试、报告下载 必须检查完整任务结果和资源回收。
接口文档与对照 查接口参数、错误行为和 FreeSWITCH 差异 历史绿色只代表对应的有限断言。

active 是当前进程配置，desired 是已保存的待启动配置。多个写入页共享 revision；收到 HTTP 409 时应重新读取并合并草稿。CSRF token 保护本机管理写入，但不是远程账户认证。远程查看后台应使用已有的 SSH 运维通道，例如 ssh -N -L 9080:127.0.0.1:9080 your-server-alias。

5. 单路“小电话”试用

在后台“压力与电话测试”选择单路测试，按顺序确认：

  1. 发生器资源预检通过，任务进入运行状态。
  2. SIP 呼叫建立，出现预期的接通/ACK 状态。
  3. 双向媒体有有效发送和接收记录，测试按键能够按合同产生 DTMF 结果。
  4. 通话挂断后，媒体会话、端口和队列按报告清理。
  5. 下载任务报告，保存任务 ID、服务版本、配置摘要与日志时间范围。

小电话使用隔离 SIP/媒体模拟端点，不调用浏览器麦克风，也不代表真实运营商线路已打通。若不能完成第 1–4 步，先排障，再接入真实线路或加大并发。

6. 接入 SIP 线路

真实线路至少需要核对 sip.listen、sip.advertise、sip.upstream、media.bind_ip、media.advertise_ip、RTP/RTCP 端口范围、sip.trusted_networks 和 media.allowed_remote_networks。启用固定上游 REGISTER/Digest 时，再提供注册 AOR、服务地址、刷新策略和私有密码文件。字段、格式和重启条件见 线路注册合同。

配置完成后依次验证：注册事务、INVITE、鉴权、号码路由、SDP、实际 ACK、双向 RTP/RTCP、按键、BYE 和资源释放。注册成功只能证明注册事务成功，不能证明通话可用。

本预览的线路注册是“向固定上游注册”的客户端；它不是接受任意软电话注册的 registrar。当前没有完整多网关、通用外呼 originate、复杂转接、SRTP/ICE/WebRTC 或完整 SBC 行为。

7. IVR、DTMF 与实时音频

本地 A 腿可以按受限合同接听、播放 WAV、收集 read 按键。测试时覆盖首位/位间超时、终止键、重复尾包、播放中断、挂断取消和结果变量。RTP telephone-event 接收与本地发送、显式 SIP INFO 收号及音频内 DTMF 检测是不同路径；当前不提供完整音频内 DTMF 检测。详见 IVR 合同和 DTMF 发送合同。

ESL 默认关闭。启用入站 ESL 子集需要同时指定本机监听和私有密码文件：

./bin/rustswitch -config config/local.json \
  -esl-listen 127.0.0.1:8021 \
  -esl-password-file /absolute/private/esl.secret

客户端应关联真实通道 UUID、应用完成事件和 DTMF 结果；+OK 只代表约定阶段的命令受理。ESL 命令、事件及差异见 ESL 参考。

主工程有 G.711 实时图、PCM 下行和 RX 收音等 Agent 媒体基础。独立 ASR 候选的 mock 只验证流协议与生命周期。接入真实 ASR/TTS/LLM 需另行实现供应商适配、采样率转换、轮次取消、超时背压和业务回退。G.722/Opus 可选离线后端、G.729/G.726 受限透传不等于各格式均已接入实时转码。

8. 压力测试与验收

后台提供 500、1000、2000、3000、5000 和自定义目标。先用单路，再逐级运行；每档固定记录 codec、ptime、CPS、通话时长、媒体模式、硬件和发生器资源。资源预检需要检查隔离端口、文件描述符、CPU、内存与日志空间。用独立 Linux 地址或服务器承载高档位发生器。

判断报告时同时看实际建立/接通数、sent_packets、received_unique_packets、nominal_packets、错误与丢失、尾延迟、CPU/线程/队列峰值及停止后的资源残留。页面显示“任务未完整完成”“读取失败”或隔离端口不足时，先看任务错误、预检和进程日志；缺少完整结果不能记为通过。具体规则见 运维与压测说明。

5,000/10,000 路属于验收目标或测试参数，不是当前已认证容量。准入保护的阈值也不是服务能够稳定承载该负载的证据。

9. 日常运维、升级与回退

日常观察 /healthz、/readyz、/v1/status、任务报告、日志、媒体 worker 代次、端口占用和磁盘余量。计划停机时先停止新呼叫，再排空在途通话，保存配置、管理状态、日志、任务报告和当前 Git/Release 标识。重启后核对 active、desired 和 Guard，并复测单路呼叫及双向媒体。

灰度迁移 FreeSWITCH 时，先盘点现网网关、分机、拨号计划、ESL 命令/事件、codec、录音、队列和会议依赖；用 45 项 PBX 功能矩阵 标出缺口，再按 迁移指南 做成对互通、少量测试号码切流与回退。当前不能保证故障实例上的活动通话跨机无损恢复。

10. 故障定位速查

现象 首先检查
后台打不开 进程、9080 监听、/healthz 和启动日志。
配置检查通过但启动失败 运行目录、媒体程序路径、端口冲突、日志/状态文件权限。
注册成功但无法通话 INVITE 是否到达、鉴权、号码路由、SDP、ACK 和 BYE。
接通后单向或双向无声 宣告地址、媒体白名单、RTP/RTCP 端口、codec/PT/ptime 和实际收发包。
IVR/DTMF 无结果 播放/收号前置状态、telephone-event 协商、结果变量和完成事件。
配置保存返回 409 重新读取 revision，合并修改后再提交。
压测读取失败或任务不完整 隔离端口、资源预检、发生器日志、结果文件与服务日志。
ASR 没有真实识别文本 确认是否只运行 mock；真实供应商链路仍需集成。
