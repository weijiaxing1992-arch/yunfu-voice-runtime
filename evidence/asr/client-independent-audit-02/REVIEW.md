# 第二轮独立字节审计

9 场景通过原始 ASR1 独立解析，395 件冻结源码前后相等且仍匹配当前来源；测试与独立 mock 二进制 SHA 符合原收据。原件前后指纹未变。8k 逐样本一致，16k 以 Python 直接 127 tap 插零卷积独立复算，与实际 2560 字节一致。

过期场景记录实际检查点 15243531348291、原期限 15243429696375，相差 101651916 ns；供应商实际消费 0 字节、无 RESULT/DONE。客户端完整 Write 4 帧不等于供应商完整收到 4 帧，原始供应商只收到 1 帧 AUDIO。

等待 final 后取消场景，独立供应商确实尝试 376 字节 final，实际 Write 接受 0 字节并返回 broken pipe；attempt 原文逐字段与既有 640 样本输入一致，outbound.bin 没有混入未写出原文。客户端交付事件为空。此次已补齐首轮缺失的实际尝试证据，但生命周期仍是 unitSource 的 LifetimeDone，非真实 SIP BYE；未记录独立客户端撤权时钟，不另行声称端到端撤权延迟。

所有 9 例自有进程 wait 成功、未强杀、run active=0 且连接 goroutine join、socket 已删除。失败分支的 RX 清理由测试模拟 retired+Reap，不等同真实 Rust 回收。模拟器只校验传输内容，无识别模型、并发容量结论。

执行方式：Python 以 UTF-8 一次读完整 audit.py，再 compile/exec 并设置 __file__ 为该绝对路径；只读取既有原件并写新审计收据，不启动网络。环境系统 Python 按文件入口曾报告 UTF-8 错误，但相同字节 UTF-8 完整解码及编译成功；原始脚本、实际独立断言及其 SHA 保留，不因入口问题改变检查。receipt.json 已经存在，重复核验须使用全新输出目录，不能覆盖旧收据。
