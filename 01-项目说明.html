01 RustSwitch 项目说明

本文说明项目定位、交付组成、实现边界与版本规则，供接入评估、开发和运维人员使用。首次运行见 快速开始，逐项验收状态见 当前能力与验证状态。

产品目标

RustSwitch 是面向电话呼入、呼出及语音智能体的开源实时语音内核，历史工程与交付材料中也使用“云蝠 Voice Runtime”名称。项目采用 Rust 媒体内核、Go 控制面、C/C++ 编解码适配，优先完善线路接入、呼叫生命周期、实时收音与播放、按键采集和资源保护，并逐步兼容有实际迁移价值的 FreeSWITCH 接口。

项目的职责是为电话业务与语音智能体提供信令、媒体及控制基础。线路运营商、SBC、ASR/TTS 服务和业务模型由部署方接入；当前代码没有内置完整的 ASR–LLM–TTS 业务系统。采用现有 SIP 发起端的用户可以评估已支持的桥接路径；依赖完整 FreeSWITCH 模块体系的用户，应先按命令、事件、配置和通信场景逐项核对迁移条件。

同硬件、同音质和同业务功能下更高并发、更低 CPU/内存，以及 1000/5000/10000 路、72 小时混合负载，是研发和验收目标。当前没有证据支持“100% FreeSWITCH 等价”“万路完整 Agent 已通过”或“任意故障零丢包”。

技术栈与运行形态

层 当前真实实现 关键边界
Go 控制进程 SIP 对话/注册/认证、路由、有限 ESL/IVR、准入、媒体监管、HTTP 后台、日志、压测管理 不是完整 Sofia/PJSIP；没有通用公开外呼 HTTP 或已实现的 ESL originate
Rust 媒体进程 多分片、单写媒体状态、非阻塞 UDP、RTP/RTCP、G.711 图、PCM 下行、RX 观察 Linux 批量接收；macOS 兼容路径；活动会话不跨分片自动迁移
C/C++ 适配 编解码 ABI、G.711 示例、固定 G.722/Opus 原生后端 不能直接装载 FreeSWITCH mod_*.so；原生协议 ABI 为预留
管理界面 HTML/CSS/JavaScript 内嵌在 Go 可执行文件 无单独 Node 服务，无 CDN；管理监听限制在回环地址
数据与工具 JSON 配置、JSONL 事件、管理状态文件、callbench、Python 验收工具 没有已交付的数据库集群、消息总线或 Kubernetes 控制面

主工程的 control/go.mod 要求 Go 1.23，并固定使用 golang.org/x/sys v0.30.0；Go 依赖源码随 control/vendor/ 提供。Rust 声明的最低版本为 1.85，依赖由 media/Cargo.lock 固定，离线源码位于仓库根 dependencies/rust-vendor/。交付脚本要求 Python 3.9+，原生适配还需要 C11 编译器。声明的最低版本组合尚未全部实测，已有构建记录使用 Go 1.27.1、Rust 1.98.1。

已具备的业务基础

  1. 可信 IPv4 SIP 中继间的 UDP/TCP/TLS 双腿呼叫、单固定上游 REGISTER/Digest 客户端、本地精确号码接听。
  2. 同格式 relay；有限 PCMA/PCMU 双腿处理与本地 A 腿图、提示音/WAV、DTMF 接收/发送与受限 read。
  3. 本机同 UID 的 RVA1 流式 PCM 下行；RXS2 本地 A 腿原生收音；带代次、会话和轮次的旧数据隔离。
  4. 并发/CPS/建立中限制、分片过载保护、排空、资源和生命周期日志、可视化配置与隔离测试。
  5. 独立 ASR 候选包含代理协议、按需 8→16 kHz 转换、结果来源校验、取消和清理实现及对应历史验证。模拟代理返回 PCM 摘要；真实厂商 ASR/TTS/LLM 尚未形成完整产品闭环。

上述内容表示存在相应实现，具体参数、错误行为及验证范围仍以接口合同和证据为准。尤其应区分编码协商、RTP 透传、离线编解码和实时转码：G.722/Opus 原生后端可供独立探测与离线 SDK 使用，尚未接入完整实时处理路径。

采用与评估流程

  1. 选择固定 Release 或提交，记录平台、主工程或候选版本及使用的配置。
  2. 按快速开始完成文件校验、配置校验和隔离单路 SIP/媒体测试。
  3. 列出实际线路、编解码、ESL 命令、IVR 动作和媒体接口，逐项核对合同及 FreeSWITCH 差异。
  4. 在代表实际业务的环境中验证失败处理、资源回收、负载和音频正确性，再评估是否进入试运行。

编译成功、管理页面可打开、某个探针通过与完整业务验收是不同层次。历史测试事件数量或对照目录条目数均不能直接换算成兼容率。

尚未完成的产品范围

真实 ASR/TTS 供应商、VAD/自动打断、双轨录音、完整 Agent 编排、G.722/Opus 实时处理、WebRTC/SRTP/ICE、完整 SIP 扩展、终端注册服务器、多网关、完整 originate/转接、任意 XML/Lua、会议/传真/视频和跨机存量会话接管，均不能由当前局部能力推导为已完成。当前主工程仍有 PCM 证据有效性门禁问题，候选存在字段字典与机器合同不同步问题。具体工作包和完成条件见 项目未完成清单。
