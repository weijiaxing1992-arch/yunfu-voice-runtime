源码目录、子命令与测试索引的使用范围

所有FreeSWITCH来源固定到v1.11.3提交 ef32e205295e29f034f1453ad245ba5efb07b94a。所选712文件与Git tree blob及SHA256对照，原始源仅保存在工作目录，不随标准包重分发实现代码；包中保留名称、参数表达式、声明位置和来源链接。

源码目录

source-catalog.json 与对应CSV包含538个四类注册宏位置、144个具有所选源码的模块目录、94个事件枚举标识、100个公共变量宏、1865个C函数声明位置及875次未注释vanilla参数出现。

这些计数都不是完整运行期接口数或已兼容数量。明确保留以下缺口：

  • 不运行C预处理，条件编译、平台/构建选择与运行加载状态尚未判定；同名和重复声明保留。
  • 17个注册表达式需人工核实，其中12处是帮助语法为NULL，1处名称是变量；NULL不代表无参数。
  • 不递归解析全部处理函数的参数文法。另附会议84条静态子命令和Sofia解析路径；其他模块继续按处理器与运行基线扩展。
  • 事件枚举含ALL订阅哨兵和CLONE等内部标识；CUSTOM子类、头字段、事件触发条件及因果顺序另由行为合同覆盖。
  • 变量宏不穷尽字符串常量、模块变量、用户自定义变量和运行期变量。
  • C声明目录保留1860个不同名字的1865个声明位置，排除了C++类方法和宏定义本身。宏生成hook、普通extern、C++/SWIG绑定、结构体布局、函数表、最终动态导出、弱符号与平台调用约定仍需完整ABI审计。例如 switch_core_event_hook.h 的宏生成hook不在此直接声明目录内。
  • XML只提取未注释的param名称和原始value表达式，不求值include、变量或模块条件，不是配置schema；必须保留原文件/profile/binding上下文。
  • 第三方/商业/外部依赖模块需由实际加载产物加入清单。没有把“源码未找到”处理为无需兼容。

函数和参数标识用于互通与定位。实现及许可来源见 FreeSWITCH固定仓库；如后续复制或分发实现代码，必须保留对应文件的原始许可与署名要求。

重建

准备与固定提交一致的完整官方源码，运行：

python3 tools/build_catalog.py \
  --source /path/to/freeswitch \
  --manifest catalog/reference-source-manifest.json \
  --output catalog

从本标准目录执行。工具先检查清单中的每个文件SHA256，任何缺失/变化会失败；它仅重建JSON和六份CSV，不下载源码、不运行原版、不执行C预处理，也不生成认证结果。Markdown注册表和手工子命令说明需在源码版本更新时同步复核。

用例索引

conformance-cases.csv 和JSON按文档中的唯一ID收集功能/切换案例及独立容量档案，全部标为not_run。每一行是场景定义，需要结合模块、参数和状态展开为可执行测试；CSV不是即开即用的压测脚本，行数不等于最终冻结测试分母。

verification.json 仅记录本标准包的静态检查，不能作为FreeSWITCH运行结果或兼容认证。
