# 兼容验收记录模板

这四个文件是可复制的记录起点，遵循 [01 · 范围、基线与统一契约](../01-scope-and-contract.md)。JSON 文件可以直接解析，**不代表已经采集现场数据、运行差分测试或取得认证**。固定源码基准为 FreeSWITCH v1.11.3、提交 `ef32e205295e29f034f1453ad245ba5efb07b94a`；实际二进制及部署资产的哈希尚未知。

| 文件 | 使用单位 | 填写目的 |
|---|---|---|
| [baseline-profile.json](baseline-profile.json) | 每种基准构建、配置及依赖组合一份 | 冻结二进制、模块、配置、脚本、客户端、第三方依赖、业务可达接口与强制用例分母 |
| [interface-contract.json](interface-contract.json) | 每个接口及其可区分契约一份 | 描述参数、状态前提、同步与异步结果、事件偏序、副作用、错误、竞争、超时重试和权限 |
| [certification-report.json](certification-report.json) | 每个候选构建、基准 profile 与测试集组合一份 | 保存逐用例结果、冻结分母、未解决项、证据及五类独立结论 |

## 填写规则

`null` 表示未知或尚未采集，不得替换成一个形式正确但不存在的 SHA、时间或版本。`[]` 只是尚未填入条目；必须结合 `collection_status`、`enumeration_status`、`complete` 等字段判断，不能将空数组理解成“完整集合中没有问题”。`entry_fields`、`case_entry_fields` 等是人工填写提示，不是已经存在的资产或测试记录，也不是 JSON Schema。

1. 复制模板到独立的验收记录目录，分配稳定的 `profile_id`、`contract_id` 和 `test_case_id`。原模板保持未认证状态。
2. 采集真实运行资产。文件使用实际字节的 SHA-256；目录或集合使用包含相对路径、文件哈希与必要属性的清单，并计算该清单自身的 SHA-256。不能把 Git commit 或 Git blob SHA 当成二进制 SHA-256。
3. 补齐静态目录没有展开的子命令、动态注册、配置引用、脚本调用、第三方接口和合法业务路径。空帮助文本不等于无参数。冻结前排除的条目必须有参考构建和使用清单依据，失败后不得移出分母。
4. 对接口先采集原版基线，再记录候选结果。原始字节、解码字段、事件、媒体、文件/数据库副作用分开保存，通过证据 ID 和哈希关联。
5. 在 scope 清单中冻结全部强制接口与用例；记录冻结者、时间、版本和清单哈希。发现遗漏时递增 scope 版本并重新验收，不能继续引用旧分母。
6. 报告按冻结测试清单逐项填结果；完整核验并评审后才允许改变认证结论。这里不提供可自动授予认证的程序。

`reference_source` 表示本标准指定的源码参考。`baseline_runtime.source_commit_observed`、`version_output`、二进制和依赖哈希必须来自实际采集，不能从参考版本推填。第三方模块、脚本、本地扩展、原有 SDK 和服务管理脚本同样需要哈希及依赖记录。

## 状态与统计

| 状态 | 含义 | 可计通过 |
|---|---|---|
| `draft` | 文档或契约尚未完成评审 | 否 |
| `not_captured` | 尚无原版或候选的运行样本 | 否 |
| `unknown` | 成员、行为或结果尚未确定 | 否 |
| `not_run` | 已列入测试清单，但尚未执行 | 否 |
| `failed` | 已运行且强制断言失败 | 否 |
| `skipped` | 已在冻结范围内，但被跳过 | 否 |
| `blocked` | 已在冻结范围内，因环境或依赖无法执行 | 否 |
| `unsupported` | 候选未实现该强制功能 | 否 |
| `passed` | 已运行并有可核验的通过证据 | 是 |
| `not_verified` | 某项整体结论尚未具备证明 | 否 |
| `not_certified` | 尚未获得本 profile 的认证 | 否 |

契约实现状态还可使用 `in_progress`、`implemented_unverified`；只有相应强制差分用例及证据通过后才可记 `verified`。实现状态不替代 `differential_test` 结果。确实不适用的接口能力应在契约中使用 `applicable=false` 并附基线证据；不能把冻结强制用例改为不适用来绕过失败。

报告的强制用例计数采用互斥分类：`passed + failed + not_run + skipped + blocked + unsupported + unknown = total`。每个强制用例必须恰有一条结果，不允许缺行或重复行；结果中的接口 ID 必须属于冻结清单。接口级结果独立汇总：一项接口的所有强制契约/用例都通过且无未知项才可记接口通过。

当前模板中分母和各项计数均为 `null`，不是 0；`compatibility_percentage` 为 `null`，禁止从静态注册数或空结果集计算百分比。分母未冻结、清单未完整或强制项未知时不展示兼容通过率。任何强制失败、跳过、未运行、阻塞、不支持或未解释差异都会阻止认证。

## 证据与归一化

证据记录至少包含路径、SHA-256、采集时间、用例、原版/候选身份及二进制哈希。接口样本中“入队成功”“开始执行”“最终完成”“资源释放”应分别记录，不能凭同步 `+OK` 认定业务已成功。

默认逐字节比较。结构比较、UUID 双射映射、时间偏移等只在归一化白名单逐字段登记后启用，每条规则需业务依据、基线样本、正反例测试和评审记录。不能整体删除时间、ID、错误字段或事件来消除差异；事件只规定已验证的因果偏序，不假设跨呼叫的全局顺序。

## 五类结论分别出具

| 报告结论 | 必须独立证明的内容 |
|---|---|
| `usage_compatibility` | 冻结 profile 中全部强制接口、行为和业务副作用符合参考 |
| `native_module_binary_compatibility` | 原模块文件无需重编译，实际宿主ABI、依赖、回调与生命周期全部通过 |
| `performance_10000_calls` | 冻结 Linux 硬件和媒体场景下，足额万路负载、持续时间及媒体/信令/资源阈值全部通过 |
| `drain_switch` | 同服务地址下新呼叫转向候选，旧呼叫排空；注册/订阅/ESL/作业处理和回退符合约定 |
| `live_migration` | 在途呼叫连同信令、媒体、脚本/队列/定时任务、外部副作用所有权接管及故障回退通过 |

这五项目前全部 `not_verified`、`certified=false`。接口使用兼容不自动推出原生二进制兼容或万路容量，排空切换也不证明在途接管。对外声明必须限定到已验证的那一项，附 profile、构建哈希、测试集及通过日期。

本模板未执行 FreeSWITCH/RustSwitch 对照或容量测试；交付时只检查了 JSON 语法、固定版本字段、未认证初始状态和必要字段。
