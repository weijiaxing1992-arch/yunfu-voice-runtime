# 真实音频处理压测与能力目录（1.10）

本轮在管理后台新增可选择的 G.711 双腿音频处理测试。此文描述接口合同，实际通过范围以对应运行收据与最终报告为准。完整语音智能体、5000/10000 路处理容量和 FreeSWITCH 全功能兼容仍需独立验收。

## 页面操作

在“压力与电话测试”选择“同编码 RTP 透传”或“G.711 双腿音频处理”。默认透传，选择与主服务生效模式相互独立。G.711 仅支持 PCMU / PCMA、8 kHz 单声道、20 ms，每通两个方向。A 腿选 PCMU 时 B 腿为 PCMA，反向选择同理。

运行总览从 `/v1/tests.current.samples` 显示隔离任务的真实活跃、接通、RTP 收发及解码/编码帧。主服务统计另列；不存在的处理统计显示“—”，失败或过期采样不会伪造零值。任务结束后这些数值是历史值。

## 请求示例

```json
{"request_id":"g711-pressure-001","mode":"pressure","concurrency":500,"cps":100,"duration_seconds":10,"payload":0,"media_processing":"g711"}
```

向 `POST /v1/tests` 提交，沿用同源校验、CSRF 与幂等规则。旧请求省略 `media_processing` 或传空值均规范为 `relay`，同键同参数不会重复执行。未知模式或 g711 配非 0/8 载荷返回 422。单路快速测试使用 `mode:"phone"`、`concurrency:1`、`cps:1`。

测试实例冻结自己的模式，禁止继承主服务真实线路注册、路由、提示音目录或本地 IVR。目标并发不会被自动调低；资源预检不足会保留明确失败报告。端口可规划不等于对应档位性能已通过。

## 媒体与判定

发生器 CLI 新增 `--media-processing=relay|g711`。g711 使用最多 32 组共享端点、64 个 RTP 接收工作者，按“本地接收 socket + 协商的媒体来源”分流。独占连接端点只供不超过 32 路的诊断测试，大档位使用共享端点；没有采用每路创建媒体线程的模型。

每帧 160 个音频样本使用 16 个固定 PCM 电平生成，前 16 个样本携带呼叫、方向、帧序号和校验，其余 144 个样本同样依身份独立生成。发生器使用独立 G.711 公式解码，全部样本固定最大量化误差 512。此检查针对有损跨律内容，不把改载荷号、只核对标签或静音包视为成功，也不等同真人听感测试。

g711 报告包含 `processed_media`，分别列出内容错误、串流、格式、时间戳、序号、身份、迟到、集中补发和发生器迟到。源计划到接收上限固定 80 ms，含 40 ms 图缓冲；同腿输出间隔小于 5 ms 的集中补发单独记录。阈值不因某次失败而调宽。

原有每路每方向 98% 名义负载、全量唯一收包与零错误要求保持。正常停止输入后允许每腿最多 6 帧有限 PLC 尾帧，逐样本单列验证，不计入源音频唯一收包。worker 实际解码帧必须等于源发送帧，编码帧与解码及 PLC 对得上。

最终还须核对：请求与发生器模式和两腿格式相同、所有 worker 健康且未重启、全部 22 个处理统计完整、8 桶直方图有效、拆线后资源归零、日志落盘无丢失、进程端口完整清理。最终 worker 统计的 `sampled_at` 必须晚于发生器退出；不允许复用旧的零状态。

前端只有在完整 g711 报告、`processing_verified`、`generator_contract_verified` 和 `worker_stats_after_generator_exit` 都成立时显示检查通过。历史 relay 报告保留原记录，不能改为转码通过。

## 有界错误诊断

g711 新报告可附带 `processed_diagnostics`，版本 `g711-observation-v1`。`observed_content_valid_packets` 对归属正确的完整 160 个 PCM 样本独立核对，包含时间戳失败的包；其中时间戳错误数与超过 80 ms 接收期限的数量另列。这些观察不计入成功接收，不能抵消丢失或改变通过条件。原 `processed_media.late_packets` 只统计通过内容与时间戳检查的源音频，不能用它的零值证明被拒绝包也没有迟到。

每个方向只保留首个接收错误及首个发送迟到，最终分别按真实观察时间选取最早 32 项，省略的方向数明确记录。接收样本保留最多 172 字节原报文及前后 RTP 时间位置，可区分音频内容损坏与持续时间轴偏移；热路径不分配逐包日志。发送诊断记录 `writeBatch` 适配器调用前后时间和成功提交字节数。portable 模式的一次调用可以包含多次 UDP 写，Linux 模式可以包含批量调用重试；这些时间只能界定整个适配器调用区间，不能推断批内每包的精确内核提交时刻。

页面“查看音频时间轴与发生器首错”展示这些原始定位数据。历史报告没有诊断字段时保持“未提供”，不补写零值，也不重新授予通过。

## 生效模式与能力

SIP 与媒体配置页可保存 `media.processing` 草稿。保存不会重启服务或改变在途通话。`relay` 保留同格式透传；`g711` 是真实 G.711 图，1.11 候选增加独立能力握手的[本地单腿 IVR/PCM](processed-local-reference.md)。本管理压测仍测双腿图；G.722/Opus 实时转码、ASR/TTS/VAD 和实时录音尚未接入，不能把本地功能用例当作双腿容量证明。

`GET /v1/codecs` 目录版本 1.1.0 新增 `runtime_media` 和 `live_codec_profiles`。`runtime_media` 每次读取当前进程真实 ready 握手；预期分片缺失、旧版本缺能力、无有效进程身份均不就绪。只有显式启用 g711 且全部预期分片健康声明 `processed_g711_v1` 时，顶层 `live_transcoding=true`。

`codec_profiles` 仍是全部测试预设；当前 g711 模式的 `live_codec_profiles` 只有 PCMU、PCMA。原生 SDK 自检仍独立缓存，其 `live_transcoding=false` 描述离线 SDK 入口；不能拿库加载成功推断实时处理能力，也不能用它否认另一个已握手的 G.711 实时图。

## FreeSWITCH 对照

| FreeSWITCH 能力 | 本项目对应 | 当前范围 |
| --- | --- | --- |
| 核心会话跨 Codec 解码/编码 | Rust G.711 PCM 双腿图 | 部分实现；仅 G.711 8 kHz / 20 ms，其他 Codec 实时图待接 |
| `show codecs` / Codec 模块 | `/v1/codecs` | 自有 HTTP 目录，不是 ESL 正文或二进制模块 ABI 兼容 |
| RTP/RTCP 会话统计 | `/v1/status` worker stats + `/metrics` | 实际处理与传输指标，字段语义分别记录 |
| 外部 SIPp/媒体发生器 | `/v1/tests` 与 callbench | 自有隔离测试工具，不是 FreeSWITCH 固有压测 API |
| 正式媒体通话容量验收 | 独立 Linux / 同机同质量基准 | 5000/10000 路处理容量、完整 Agent 负载、72 小时稳态均需独立证据 |

机器模型见 [OpenAPI](openapi.json) 和 [字段字典](schema-reference.md)；媒体协议及处理限制见 [处理参考](processed-media-reference.md)。
