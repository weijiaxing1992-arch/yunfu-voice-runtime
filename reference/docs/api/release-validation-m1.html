M1 首轮 G.711 候选：历史验证记录

本页保留 work/voice-runtime-m1 首轮候选的历史验证，不代表 v1.10 当前源码已经执行这些旧回归。最新构建与管理实测见 v1.10 发布复核。当前 build-03 / processed-03 已重新取得 22/22，新增发送方暂停恢复 4/4；旧 build-02 的新增两例均失败，管理入口三项单路及 100 路通过、500 路失败。当前build-03/testlab-02三单路及100路再次通过、500路仍失败，不能用本页历史通过覆盖后续失败。

本轮已贯通 RTP → 重排 → 8k PCM → G.711 编码 → RTP，两腿可分别使用 PCMU 与 PCMA。代码、配置和协议有中文注释，详见接口及行为合同与实际验证摘要。

本页记录的 M1-G711-final-02 当时未替换 9080 主服务。v1.10文档结果来自隔离候选；运行后台实际版本以 GET /v1/docs 的 version 字段及发布回执核对。新功能采用显式 media.processing=g711，目前限双腿、8k单声道、20ms；默认 relay 保留原用法。

修复及验证

  • CN结束后合法时间戳换相位，恢复语音不再持续被拒包。
  • 媒体worker暂停140ms后，保持原播放期限并丢弃过期帧；修复前会永久多出约50ms延迟。相同严格测试修复后恢复首帧为原400ms位置，过期的380ms位置不重放。
  • 迟到按键结束包保留原事件时间戳，不覆盖较新的活动按键；缓存固定且无法恢复的旧事件明确丢弃。
  • 迟到CN、按键恒定起点和发送抖动不再倒推RTCP SR媒体时钟。
  • 固定容量期限堆、有界编码缓存、借用PCM和发送前再次核对时钟，避免逐帧创建任务与追赶发送积压声音。

FreeSWITCH对照变化

源码文档中的原始3988个ID全部保留。key-media-transcoding从“未实现”改为“部分实现”：未实现由2845减为2844，部分实现由52增为53。RTP、RTCP、SDP、分配和连接的既有行补充处理模式范围；内部jitter不等于已经实现 uuid_jitterbuffer 或拨号计划 jitterbuffer。

首轮没有对新M1场景运行原版FreeSWITCH成对验证，也没有将本地通过数直接写成原版兼容率。当时后台绿色仍来自1.9证据；目前v1.10候选已按新源码重跑固定26项并更新正式JSON，但它仍不是新处理图的原版音质/容量认证，运行后台版本另以 /v1/docs 的 version 字段核对。绿色必须由对应完整证据门禁生成，不能手工改计数。

当时后续工作与本轮进展

  1. v1.10 候选已将新处理能力合入 /v1/codecs、管理测试模式和独立逐 ID 门禁；目录握手与原媒体验证各自保留证据。
  2. 新发生器已核对真实 G.711 内容；历史 build-02 管理入口 100 路/30 秒通过、500 路失败，build-03修复同源暂停恢复后已再次管理复测，100路通过、500路仍有内容/序号/过密到达异常而失败；1000/5000/10000 路处理容量仍待验收，不能沿用旧 relay 结果。
  3. 接入G722/Opus实时编解码、按需重采样与处理图上的播放/IVR；随后推进流式ASR/TTS、Turn取消、VAD及双轨异步录音。
  4. 以相同硬件、音质和全部辅助进程资源，验证相对FreeSWITCH的性能及稳定性目标。

主服务1.9的总览已能显示隔离压测实例的实际呼叫和媒体数据，本轮没有将其500路透传短测结果外推为处理图性能。5000/10000路处理容量、完整Voice Agent、1.5倍性能和72小时稳定性均尚无本轮通过证据。
