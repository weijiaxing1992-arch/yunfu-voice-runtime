v1.11：本地单腿 PCM 与 IVR 验证记录

本轮实际修复

启动握手现在要求固定 id=0，错误 ID 不会建立健康 worker。另一个真实 UDP 反例发现 484 字节复合按键包先产生收号事件、随后才被图拒绝。修复将共用 480 字节上限校验前置到事件采集之前；本地和桥接处理图的超限包均无事件、无发送且只增加无效计数，480 字节边界及正常短包仍通过，relay 的原包透传保持。修复前失败原文与修复后回归独立保留。

媒体图正常 PCM/RTP/RTCP 使用固定缓冲，但整个 worker 仍有有界计时器、按键日志和任务释放开销，尚无全 worker 热路径零分配结论。20ms 过期期限也不等于任何负载下都能保证最小包间隔；真实质量门槛继续保留。

后台页面的实际单腿观察

使用内嵌119份文档的 admin-build-01 隔离实例，浏览器实际观察到本地活跃1路，PCM消费为1,546帧/247,360样本；挂机后变为0路，累计消费保留1,998帧/319,680样本，能量最大值为1,982,949,216。页面本地处理就绪为1/1，FreeSWITCH对照四卡为71通过、3916未运行、1失败、0无效，显示文档版本1.11.0。DOM、实际worker统计、原帧和清理结果保留于 work/voice-runtime-m2-local/ui-local-01。

这个页面观察夹具在五个8秒发送段之间读取HTTP统计，不能当作连续媒体质量负载。实际收到2000个RTP包、解码1989帧、消费1998帧，保留9个迟到和9个PLC；没有将补偿计成真实解码，也没有把页面显示正确解释为媒体零缺口。正式独立26项音频场景与本次UI观察分别记录；该实例正常退出，主服务9080未用于本次单腿呼叫。

收到的2000包中，1989包解码、9包迟到，另有2包未消费。通话释放会取消计时器并销毁图中的待消费缓冲，此次差额与该行为一致；缺少释放前的队列深度及截止时间记录，不能将2包逐包归因为尾部取消。processed_queue_reset_drops 不统计 Release 销毁的尾部缓冲，因此该指标为0不表示已收到的所有包都已消费。消费累计包含9帧PLC，并不因通话释放清零。
