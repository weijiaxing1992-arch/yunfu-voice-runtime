2026-09-06 逐项核查、编码与压力实测记录

本轮完成固定目录逐条核查及当前已实现路径的本地回归，并修复发现的问题。原版 FreeSWITCH 成对运行验收尚未执行，2,000 路媒体压力未通过，不能宣布无感替换或万路认证。

文档集：1.3.0；来源基线：FreeSWITCH 1.11.3，提交 ef32e205295e29f034f1453ad245ba5efb07b94a。核对日官方 最新发布页仍为此版本。运行环境为本机 macOS arm64、10 个逻辑 CPU；媒体和发生器共机、共用回环地址，未使用独立 Linux 压测服务器。

逐条审查覆盖与未验证内容

逐项账本保存全部 3,979 个对照 ID、来源指纹、当前实现位置、直接测试定义、缺口和下一步验收要求；没有删除未实现项以改善结果。完整树另外核对 145 项模块/SDK 目录并集、35 个业务域。每条原版运行仍为未执行，成对结论仍为 not_run。

修复与优化

  1. SIP 编码候选误拒绝：存在可接受的 PCMU 40ms 候选时，未选中的 L16 48k 双声道 40ms 不再使整份合法报价失败。格式映射和参数错误仍严格拒绝；全部候选不支持时仍拒绝。
  2. 重复成功分支放大资源：同一未选中分支的 32 次重复 200，以前产生 32 个 BYE 事务、64 个定时器；现在仍回应 32 个 ACK，但至多保留 1 个 BYE 事务、1 条清理记录、3 个定时器。全局事务预算和每通最多 8 条记录同时约束，32 秒期限不被重传延长；完成和回收最终归零。这是有限清理能力，完整多目标分叉仍未实现。
  3. 隔离端口碎片误判：按四端口块跳过已占用或受保护的端口，实际预留再交给测试进程；主服务媒体范围继续保留。500/1000/2000 档位已实际进入呼叫测试。端口能分配不代表性能达标。
  4. 失败报告缺少新状态：普通媒体采样不再作为最终状态。发生器失败后在原总期限内最多用 1.5 秒读取新状态，保留阶段、时刻和采样错误；失败返回 null，原发生器错误继续保留。
  5. 外部验收采样中断：仅网络读失败允许有限恢复，第三次连续中断即失败，总期限不延长。JSON、业务和任务归属错误不重试；不降低媒体门槛。
  6. 音频合同与文档一致性：提供 PCMU/PCMA/G.722/Opus 原生 PCM SDK 与真实后端探测；补齐 IPC Connect 的 codec/payload、fmtp 必填及旧 PCMA 规则，区分单库不可用与整个探测失败。HTTP、字段字典及 FreeSWITCH 对照同步更新。

压力结果，包括失败

均按 100 CPS 建立目标并发，然后发送 10 秒双向 PCMU，20ms 分包。验收要求所有呼叫建立、发生器至少提供标称包量的 98%、实际发送包全部唯一收到，并满足完整清理。

500 499,952 / 499,952 99.9904% 本场景通过，实际发送包无缺失
1,000 996,640 / 996,640 99.6640% 本场景通过，实际发送包无缺失
2,000 1,891,276 / 361,380 94.5638% 未通过：缺包 1,529,896，且发生器提供率不足

500 的标称包量为 500,000；1000 为 1,000,000。未发送的包没有被算为“成功收到”，实际收包零缺失也不是无限时长、全部负载和网络条件下的零丢包保证。

第一次 2000 测试建立了全部呼叫，但外部验收脚本遇到一次 HTTP 读取超时后主动停止任务，未拿到发生器完整结果。此报告以 pressure-2000-interrupted.json 保留。修复只读采样恢复后使用相同参数复测，成功取得上述失败报告；期间仍记录一次外部采样超时和三次子实例采样错误，没有隐藏中断。

完整失败场景观察到的控制面峰值为 55 个协程、15 个 Go 线程，队列未显示堆积，全部呼叫拆线与进程/端口回收完成。这些是有限采样，不能排除采样间尖峰。该旧报告的 final_status 是修复前的媒体快照，不能据此计算完整最后一跳丢包。

为隔离路径，另运行 2000 路同样信令与端点规模，绕过 Rust 媒体转发，直接在模拟端点间发送：1,999,808 发、732,119 收、缺 1,267,689，提供率 99.9904%，仍失败。这证明同机发生器/回环路径也存在问题，尚不能精确定位内核、调度或各段丢包，更不能把直连测试当作媒体容量通过。全局 UDP 满缓冲/无 socket 计数未增加也不能排除其他内核路径损失。没有修改主机网络参数或放宽通过门槛。

尚不能闭环的兼容项

原版 ESL 认证/帧格式/事件顺序与异步命令，XML 拨号计划真实执行，Sofia 全套注册鉴权/TCP/TLS/会话刷新，会议混音、录音、IVR、Lua、呼叫中心、完整 WebRTC/SRTP/ICE，以及原生 C/C++ 模块 ABI 宿主等仍按逐项对照和模块审计保留缺口。存在配置模板、源码声明或相近 HTTP 操作不代表这些功能已兼容。

下一步需要原版 FreeSWITCH 运行环境与实际启用模块，逐个闭环 178 项未验证条目（其中 177 项为验收定义），展开正常、错误、并发和副作用断言；同时在独立 Linux 发生器/被测机上完成 2000 至 10000 路、长时间、升降载及故障场景。没有相应原始证据之前，上述结论继续保持未验证。
