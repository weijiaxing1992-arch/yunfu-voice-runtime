云蝠 Voice Runtime V1 长期目标与逐项验收

本文档包 1.13 包含已验证的内部 RX 收音，保留 1.12 的限定 G.711 双腿/本地图、PCM 轮次与 RVA1 合同；RX 限于已 ACK 本地 A 腿。实际安装版本须通过 GET /v1/docs 及部署回执核对，不能从文档包版本推定已安装。完整 M1 容量、G.722/Opus 实时处理及 M2 供应商闭环仍未通过。

本页是长期目标的验收合同，不是完成报告。依据用户提供的《Rust 重构 FreeSWITCH / Voice Agent Runtime 技术方案 V1.0》附件编写，按原文顺序保留全部 20 节；附件 pasted-text-1.txt 的 SHA-256 为 ade13e5ee6857b0253327828bcfe9a48754a425bae52d26e22364b3a563c9d09。1.9 是原始历史基线；下文现状已更新到文档包 1.13，保留 1.12 的已发布合同与本批候选测试来源，实际通过范围以冻结源码、二进制和原始证据为准。

V1 优先完成真实 AI 电话媒体链路，继续保留现有 FreeSWITCH 接口与差异记录。下文的验收编号仅用于研发追踪，不新增、删除或改变 FreeSWITCH 对照统计分母，不直接授予绿色。暂缓不等于兼容，设计不等于实现，接口存在不等于真实业务完成。

本页使用“已有有限实现”“离线基础”“未完成”“待测目标”描述现状；这些不是测试通过状态。每项关闭必须附具备原始输入、输出和资源回收结果的测试记录。缺环境、缺探针、缺少目标负载、跳过、未覆盖错误分支或过期证据分别列出，不计为通过。原目标说明见 研发方向，现有计划见 研发里程碑，历史已发布范围见 1.12 验证记录，本批候选测试见 1.13 验证记录；实际安装版本须另核 GET /v1/docs 及部署回执。

一、总体架构

目标保持 Rust Media Core + Go Control Plane + 现有 SIP 能力渐进迁移。Rust 管理实时媒体，Go 管理呼叫、路由、配置和 Agent 编排；协议与编解码通过适配层复用成熟 C/C++ 生态。V1 可由 FreeSWITCH/SBC 或 Kamailio/OpenSIPS 承担 SIP/线路适配，Rust 负责其实际接入的媒体链路。

当前已有 Go 受限 SIP 与入站 ESL、多个 Rust 媒体工作进程、受限本地 IVR、播放和收发按键。Go 与 Rust 使用有界的进程管道 JSON IPC；1.12 已有 FD3 Unix datagram PCM 与私有 Unix stream RVA1 入口，1.13 候选增加独立 FD4 RXS2。gRPC 服务及外部 ASR/TTS 供应商链路尚未实现。现有 C ABI 或离线编解码库不能直接装载 FreeSWITCH 原模块，成熟 SIP 提供器也未因预留 ABI 而完成。

验收 A01：提供一条可重放的真实电话：呼入/呼出接入、SIP 对话、RTP、业务控制、媒体结束和资源归零均可关联到同一通话；协议适配器与 Rust 媒体之间有明确责任和故障归属。若保留 FreeSWITCH，报告必须列出其职责、进程和资源成本；不能把 SIP/录音/转码移交给它后，只测 Rust 进程宣称整体性能提升。gRPC/UDS 若被采用，需独立完成连接、版本、大小限制、背压、取消、断连与重连测试。

三、线程模型

目标禁止“一通话一个操作系统线程”。媒体会话在建立时选择固定 worker，所有可变媒体状态由该 worker 修改；活动会话不自动迁移。附件的 32 核划分（4 核系统/控制、24 核媒体、4 核 DSP/后台）以及单 worker 500/1000 以上 MediaLeg 均是容量规划示例，不是当前验证值。

当前采用多个独立 Rust 媒体进程，每进程一个媒体事件循环，另有固定控制读写及受限文件加载线程。1.13 候选每 Worker 固定 RX 接收循环，Server 全局固定 4 个 RX 控制执行者、64 个在途预留；不按每通话或每帧新增固定协程。已有槽位/代次、受限就绪处理和 Linux 可选 CPU 亲和性；尚未证明基于 CPU/PPS 的最优负载分配、NUMA 收益或实时图扩展效率。现有定时结构不等于已实现附件建议的通用 timer wheel。

验收 A03：记录建呼时的 worker 选择和整个通话归属，验证双腿同所有者与旧代次拒绝；1k/5k/10k 下分别记录操作系统线程数、Go 协程、上下文切换和最忙 worker。集中建呼、挂断、慢控制、DSP 失败不能产生随通话数线性增长的线程或无限任务。hash 分配、负载选择和固定绑核方案需同 profile 测量，再选择；不得依据平均 CPU 掩盖某个 worker 饱和。

四、网络层

V1 优先 Linux 就绪循环和普通 UDP；附件推荐 epoll + recvmmsg/sendmmsg，后续保留 NetworkBackend 的批量收发替换边界。当前 mio 在 Linux 使用系统就绪机制，已有 recvmmsg 批量接收；sendmmsg、io_uring、AF_XDP 和 DPDK 没有作为现有已完成后端交付。

验收 A04：在同样的每通话端口模型下，保存真实 syscall/包数、每批大小、发送期限和尾延迟；按 socket 批量，不为了凑批等待或一次突发发送积压音频。核对 RTP/RTCP 双向端点、内核丢弃、EAGAIN/ENOBUFS、错误源与端口隔离。共享端口或新后端必须新增互通和公平性证据，不能只凭 syscall 数降低判定业务更快。只有 profile 显示网络后端是瓶颈时，再评估 io_uring/AF_XDP/DPDK。

五、RTP Engine

验收对象完整保留：RTP、RTCP、SSRC、Sequence、Timestamp、Payload Type、Marker、RFC4733 DTMF、Packet loss、Reordering、Duplicate、Jitter。接收和发送方向各自维护状态，不能把中继收到的流与本地生成流混为一个序号空间。

R02 SSRC/序号/扩展序号、32 位时间戳回绕和 marker；每方向 packet/octet 计数可追溯 relay 保留原报文；G.711 图已有独立 RX/TX 身份和时间状态，完整线路/长稳仍待验

六、Codec 设计

V1 核心编码保留 PCMA、PCMU、G.722、Opus、PCM16。Rust 对外提供明确的 decoder/encoder 合同，输入、输出容量与错误由调用方验证；成熟 G.722/Opus C 库经安全 FFI 复用，不要求为纯 Rust 重写所有算法。G.711 LUT/SIMD 是可测优化选项，不能未测就声称性能收益。

当前已具备 Rust G.711、固定 SpanDSP 子集 G.722 和固定 libopus 的离线编码/解码，实际可用性依赖后端探测。G.711 双腿 RTP → Decode → PCM → Encode → RTP 已在 v1.10 完成限定功能验证；500 路仍失败。本地 A 腿 PCM/IVR 已在 v1.11、轮次与 RVA1 在 v1.12 限定交付，实际结果见 已发布记录；1.13 候选 RX 保持原生 8k/20ms。G.722/Opus 仍未接入实时图，完整 ASR/TTS/VAD/录音闭环尚未完成。

验收 A06：每种核心编码分别记录已加载库/来源/许可、帧长、声道、PCM 率、RTP 时钟和实际连续内容；编码器拒绝错误输入尺寸，不越界、不无界分配。G.722 PCM 16 kHz / RTP 8 kHz、Opus RTP 48 kHz 必须单独断言。丢包、CN、历史补偿与原生 PLC 不伪装真实解码；后端缺失、FFI 错误和释放均有负例。PCM16 SDK 小端与 RTP L16 大端分别验证。质量需使用相同样本、编解码参数和明确算法指标/听评，不以字节大小或低 CPU 替代。详见 音频 SDK。

七、统一 AudioFrame

统一的是格式元数据、媒体时间和所有权，不强制全部先变成 16 kHz。保留源采样率，按分支需要重采样：G.711 可以保持 8 kHz，ASR 需要 16 kHz 时只转换 ASR 分支；24/48 kHz TTS 在电话输出分支转换。

当前离线 AudioFrame 已支持 8/16/24/48 kHz、单声道 S16LE、精确 10/20 ms、最多 960 样本，具有显式 AudioPosition/RtpPosition；原入口保持 16 kHz。来源由 AudioOutput/FrameOrigin 区分。1.12 已有带 turn_id 的原生 8k 下行，1.13 候选 RXS2 以显式 kind/来源/缺口/固定期限输出 A/RX；完整通用 AudioFlags/池化 AudioBuffer 及实时分支重采样仍待补齐。

验收 A07：同一帧的 pts/媒体时间、sample_rate、channels、有效样本和来源一致；所有支持采样率/帧长、错误尺寸、溢出、RTP 回绕都测试。离线分支同率移动所有权，异率转换，时间倒退/重叠拒绝，缺失/CN 不伪造 PCM；滤波延迟显式记录。实时接入后重做长通话漂移和所有权回收测试，不把离线通过当作实时图通过。Clone 和导出仍可能复制/分配，当前不宣称全链路零复制。

八、Audio Graph

目标是显式媒体数据流：接收、报文处理/解码、AudioFrame、Gain/VAD、录音与 ASR 分支，以及 TTS、重采样、Gain/Fade、编码和发送。附件的 Node 接口作为设计输入；报文重排、解包、解码和播放时钟的确切先后要写进执行合同，不能仅照图连接而丢失 PacketLoss 语义。

首版采用有限静态模板，不实现任意动态 DAG。已发布 G.711 bridge/local 图包含原生 8k/20ms 解码/编码、有限 tone/WAV 与 PCM TX；1.13 候选增加只观察本地 A/RX 的独立上行队列。任意动态图、供应商/VAD/录音和其他 Codec 实时节点未完成。

验收 A08：会话建立前验证节点、编码/采样率、缓冲、预算和执行顺序；帧边界切换图版本，旧版本不继续输出。热路径不解释 XML/脚本、不读文件、不查动态配置、不等待外部服务。验证分支慢消费者、取消、异常节点、图错误、样本归属与时间同步；没有输出副作用的空节点不能通过。一个有界图模板先贯通真实电话，再扩展其他模板。

九、ASR / TTS 接入

目标让 Media Worker 与网络 AI 适配器隔离，经有界队列传递音频和状态；ASR/TTS 使用真实流式协议/连接。1.12 已有有界 PCM 下行；1.13 候选已验证原生 8k/20ms RXS2、Go SDK 与已 ACK A 腿 Server 授权，媒体 RX 不占用 TX 互斥。这些内部基础没有外部 ASR HTTP/WebSocket 接口，不是供应商闭环或已交付的 ASR/TTS SPSC 管线。

候选收音按 Graph 原始观察建立不可续期 100ms 期限，覆盖 Rust、OS socket 与 Go 停留，接收/Read/Server 交付分别复核；旧语音、时钟错误、缺口、CN、PLC 不当作正常用户静默。每层队列各有上限，取消或 unknown 保留清理句柄，挂机先撤权后真实释放。供应商适配器使用帧前仍须 CheckFresh，不能将最后检查点、函数返回及写外部服务当原子保证。真实 SIP 四组、进程暂停四组的限定证据见 RX 合同，它们不关闭 A09-ASR 的供应商验收。

验收 A09-ASR：持续上传对端 RX 轨，正确采样率和时间；按协议验证连接、部分/最终识别、超时、断线、重连和错误。ASR 停止读取时，队列条数/字节/音频毫秒有硬上限，丢弃或流重置显式报告；不把用户语音无声删除，不把自身 TTS 混入 RX 识别。

验收 A09-TTS：真实流式请求、首块/后续音频、结束与错误；正确转为电话采样率并按媒体时钟播放。覆盖突发数百毫秒音频、慢响应、中途失败、取消后迟到和连接耗尽。worker 不能 await 模型响应；模型延迟不拖垮其他通话。先用保留真实 WebSocket/gRPC 协议和连接成本的可控服务，再接实际供应商；空函数或文件一次读入不等于流式供应商验收。

十、打断机制

目标以单调 turn_id/生成版本关联 LLM、TTS 和所有待播放音频。用户打断使旧版本失效；排队、适配器回流和最后发送之前都检查版本。向上游取消与本地停止并行，不能等上游应答后才阻止旧音频。

1.12 已实现有界 PCM turn、递增 ID、迟到音频拒绝、原子替换及 0/20/40ms 中断，淡出只消费已排队的至多 1/2 帧，不续期。uuid_break、按键终止 WAV/tone 保持各自应用语义，不自动映射 PCM INTERRUPT。VAD 自动触发、ASR/LLM/TTS 统一轮次和真实业务打断时延仍未完成；1.13 候选 RX/TX 可并行不等于完整抢话已验收。

验收 A10：Turn 100 被 101 替代后，故意延迟 500 ms 返回的旧 TTS 不再产生新发送包；覆盖已排队、正在转换、上游迟到、连续两次打断和会话释放。记录用户讲话、确认打断、停止旧音频、最后旧包提交等时间，且打断期间持续收音，RTP 时间线不复位。网络和终端缓冲中已经提交的数据不能撤回，应报告边界。

验收 A10-FADE：分别实现并测试立即停止、20 ms、40 ms 淡出，验证样本包络、时长、结束事件与取消后静默/新轮次边界。20–40 ms 是原文建议范围，默认值需经 A/B 测试冻结；未经测量不宣称最佳听感或端到端立即静音。

十一、Jitter Buffer

目标先实现轻量、可界定的序号重排和播放缓冲，再根据测量选择固定或有限自适应模式。原文建议 min_delay=20 ms、target=40 ms、max=120 ms，这是待实现/按线路冻结的参数，不是当前运行配置默认值。已发布 G.711 图具备有界重排、播放期限、有限历史 PLC 和明确缺失；relay 仍为透明路径。完整可配置范围、所有线路/Codec 及质量指标尚未验收。

验收 A11：确定序号窗口、最大条数/字节/时长、播放期限、SSRC 改变与回绕规则；注入可控乱序、突发、重复、迟到、丢包、DTX/CN，验证及时输出与有界内存。逐项报告 late_packet、lost_packet、reordered_packet、jitter_ms、buffer_delay_ms，区分 RTCP jitter、排队延迟和发送迟到。丢失帧不能误判为用户静默；PLC/FEC 质量与额外等待单独验收，不能靠无限增加缓冲掩盖抖动。

十二、内存模型

目标是 worker 自有 PacketPool、AudioFramePool、PCMBufferPool，跨线程一对一通道可选有界 SPSC；512 B/1 KiB/4 KiB 块为附件示例，最终大小依据真实载荷与帧率确定。

当前已有固定媒体槽位、有界队列/缓存和 1.12 PCM 轮次，离线帧可拥有 Vec；1.13 候选 Graph 观察器、Rust 导出及 Go SDK 各有 8 个普通槽，另外保留摘要/终态及 OS 缓冲。这些分层上限不等于上述完整实时池体系或 ASR/TTS SPSC 管线已经交付。固定槽位、文件缓存、Rust 所有权或使用 channel 均不自动证明热路径没有 malloc/free。

验收 A12：冻结池数量、尺寸、生命周期及耗尽策略，测稳态每通话分配次数、分配字节、峰值和归零；必须含第三方 codec、发送错误、图取消和长通话。池耗尽不能无限扩容；慢 ASR/录音不得长期占用实时池。SPSC 仅用于确实单生产/单消费的边界，验证满队列、关闭、取消、迟到写入和 ABA/复用风险。对比复制、锁和 allocator contention 的实际 profile 后再优化，不把所有共享数据改成无界 Arc<Mutex<VecDeque>>。

十三、录音设计

目标按 RX/TX 分轨记录媒体时间、track 和音频数据，由有界 Recording Queue 交给独立 Recorder Worker，再写本地 spool、上传对象存储；混轨作为后处理，不替代原始双轨。当前事件 journal 不等于音频录音，双轨录音链路未完成。

验收 A13：真实双向音频可解码回放，轨道独立、时间可对齐，丢包、PLC、CN、打断与静默有明确表示；长期文件时长/样本数与通话时间一致。测试慢盘、满盘、写失败、进程退出、上传失败/重试和回收；所有 I/O 在媒体线程之外。录音队列按字节和音频时间设限，必需录音失败时的继续/降级/挂机策略必须冻结并产生真实事件。保存音频内容校验、轨道清单、最终持久化结果，不能只以文件存在或 journal 成功为通过。

十七、部署架构

附件建议一台服务器部署 2–4 个 Runtime 进程，并按 NUMA 节点分配。当前已有独立媒体进程及分片故障回收，尚未证明特定 2–4 进程/NUMA 拓扑的收益。每个进程管理多少 worker、媒体与控制/AI/录音占多少核，要按机器实测冻结。

验收 A17：记录逻辑 CPU、物理核、NUMA、亲和性、IRQ/RSS/RPS/RFS/XPS、内存放置、网卡和端口分区；逐项比较基线和调优结果。杀掉一个媒体进程时，检查所属通话、其余通话音频、端口与旧代次回收、新建呼叫恢复、控制面和告警。

“崩溃影响 25%–50% 电话”只在 2–4 个进程负载均匀且没有共同瓶颈等前提下成立，不能当作承诺。报告使用实际所属通话比例与影响时间；控制/网卡/磁盘或整机故障另测。首期不承诺活动媒体跨 worker/进程/主机无损迁移。

至少分开三类 profile：

profile 必须实际执行 不能替代的结果
rtp_forwarding 真实双向RTP/RTCP转发及必要信令 不代表发生过解码、重采样、ASR/TTS或录音
codec_processing 实时Decode→PCM→Encode→RTP，指定codec/ptime/音频质量/缓冲与安全条件 离线SDK批处理、静音/空载或codec旁路不能替代M1
full_voice_agent 实际流式连接、非静音语音、VAD、TTS、频繁打断、双轨录音和失败策略 tone/WAV播放、无连接空函数、关录音或只算Rust进程不能替代M2/总成本

冻结并发定义（Call、Leg、已接通、正在建立分别计数）、CPS、突发、保持时长/分布、双向包速率、codec/fmtp/ptime、采样率、TLS/SRTP等安全条件、录音策略、模型协议与音质要求。准入保护默认档与专门容量测量档分开记录，不能临时关保护再声称原配置安全。每档的持续时间、重复次数、音质阈值和允许故障预算必须在开始前写定；缺少门槛就保持“待验收”。

资源核算与质量闭环

性能对比使用同一硬件、资源配额和等价业务配置，FreeSWITCH基线应合理调优且固定版本。计入候选与基线各自所有必要进程：Rust、Go、保留的FreeSWITCH、SIP/SBC适配、DSP、ASR/TTS适配、录音/上传、内核CPU和网络。远程模型资源/调用成本另列；本机模型则计入本机总量。发生器放独立机器优先；同机时披露竞争与其资源，不能从被测成本中悄悄混入或删去。

CPU同时给用户/内核秒、使用核数/全机占比与最忙worker；内存给同一时刻RSS/PSS或明确口径、峰值、池和队列，不能把各进程不同时刻峰值之和称为整机同时峰值。单通话成本的分母使用真正持续服务的通话时间，不使用累计创建数。总览可辅助观察，不等于完整验收，口径见 运行总览。

二十、最终系统与长期完成定义

最终目标是“云蝠拥有专门为大模型实时电话设计的 Voice Runtime”：Go承载Campaign、Agent Engine与Routing业务；Rust提供SIP适配边界、RTP、Codec、AudioGraph、Record及实时ASR/VAD/TTS媒体接口。流式ASR、流式TTS、抢话、打断、Fade、多轨、低延迟与高并发是要逐项交付的能力，当前尚未整体实现。

先用约8–12个核心模块跑出一通完整真实AI电话，再推进多路稳定容量和逐步替换；模块数量本身不是完成标准。长期目标完成至少要求：17项V1能力、10命令/11事件的冻结合同有真实正反例证据，M1→M4各门槛通过，1k/5k/10k完整档位有据，生产灰度与回退已演练，并交付架构/接口、部署、线路矩阵、容量报告和故障手册。任何未完成必需项仍公开，不能以新增目录或修改颜色结束目标。

本页不要求一期复制全部PBX功能；也不会把这项优先级调整当作FreeSWITCH 100%兼容证明。原始接口、模块与通信协议差异继续见 完整对照、兼容工作清单 和 验证账本，性能与业务闭环另按本页持续验收。
