5000路验证与本轮逐项复核

文档集 1.4.0，复核日期 2026-09-06。最终代码在隔离 Linux 虚拟机连续两轮完成 5000 路真实 SIP 与双向 PCMU 媒体验收。

每轮标称双向总包量 5,000,000；门禁保持原定的逐方向、逐流至少 98% 负载，并要求所有实际发送包被唯一接收。两轮每方向每路最低收到 499 个包，部分方向达到 500；不存在用总吞吐掩盖未发声通话的情况。

两轮日志均证明同一控制实例下 5000 路同时接通；8 个媒体分片均无重启，最终活跃通话归零，媒体 socket 丢弃及应用收发错误为零，事件日志无丢失。进程退出、端口释放和临时目录删除均由测试管理器完成并核对。

实际环境和证据边界

宿主为共享使用的 ARM64 Mac mini，10 个逻辑 CPU、16 GiB 内存；测试在 Apple Virtualization.framework 启动的 Alpine 3.24.1 / Linux 6.18.35-virt ARM64 虚拟机中执行，分配 8 vCPU、2 GiB。服务、8 个媒体分片、8 个发生器发送工作者共享该虚拟机，使用隔离回环地址 127.77.0.2、128 组共享端点、512 个端点 UDP socket。100 CPS 建立呼叫，PCMU / 20 ms，完整媒体窗口 10 秒。

测试期间为虚拟机进程持有系统提供的 latencyCritical / userInitiated 活动，结束即释放；用于降低系统节能对实时定时的影响。前期失败与最终成功之间还存在宿主负载、虚拟机内存和发生器版本的变化，不能将差异全部归因于某一代码优化。环境做法见 Apple 实时活动文档。

本结果不覆盖长时间稳定性、真实网卡/线路、转码、会议、录音或一万路；静态 musl 构建中的动态加载不可用，因此也不证明 Linux 原生 G.722/Opus SDK 转码。未执行原版 FreeSWITCH，本轮没有授予任何成对兼容认证。当前 macOS 管理页面仍执行自身端口预检，5000 路按钮不会自动调度此隔离 Linux 虚拟机。

代码修复与回归

  • 发生器在 Linux ARM64/AMD64 使用批量收发，按真实 socket 分配固定发送工作者并提前准备包缓冲。保留节奏控制、部分发送只重试未发送后缀及有界信号中断重试。
  • 5000 路拆线采用最多 64 个工作者，独立维护每路请求和超时，避免每路一个 goroutine 或串行拆线队列。逐流不足量、未知/额外包及早退读取都计为失败。
  • Rust 复用 Linux 批量接收描述符；每批重绑缓冲地址、重置内核输出，保留边沿通知一直排空到 EAGAIN 的要求，避免旧控制信息或截断数据误判。相同时刻准入计算走快路径但不补回已花费令牌。
  • XML 元数据启动时解析并有界缓存；输出快照独立持有切片，读写中的纯计算移出管理锁，保存前再次检查配置版本。慢 XML 响应不再拖住状态与排空接口。持久化提交仍包含同步写盘，慢盘场景尚需实际硬件验证。
  • 修复账本漏列 21 个动态编码用例；通过有界 AST 枚举列出定义，不执行测试文件。绿色状态单独绑定真实运行、当前源码、构建产物、完整日志和复查期限；缺失证据、过期、源码变化或失败均不会显示绿色。

全量 Go 竞态回归通过 303 个 test/subtest 事件；两种 UDP 模式共 90 项真实 SIP/媒体端到端用例通过。宿主 Rust 25 项库测试和 1 项集成测试通过；Linux 实际执行 27 项 Rust 库测试，批量系统调用布局、真实收发、截断、部分发送、每路足量与有界拆线等发生器测试通过。新开发路径均附中文说明。
